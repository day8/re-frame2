# phase-2-impl-order — the EP loop

Phase 2 is one repeatable loop over the EP index below, driven by the **pinned owning Specs** and the **live conformance fixtures** — read the contract, not prose about the contract. Every owner named here is read from the profile's verified checkout at the pin (cardinal rule 1); the `day8.github.io` links are citations of live main, never the reading route. Two standing anchors: [`spec/Ownership.md`](https://day8.github.io/re-frame2/spec/Ownership/) (which spec owns a surface) and [`spec/API.md`](https://day8.github.io/re-frame2/spec/API/) (the public signature for anything the port exposes).

## Step 0 — bootstrap the feedback seam

Before or alongside the first foundation slice, build the smallest harness seam that runs one fixture end to end. The corpus contract is [`spec/conformance/README.md`](https://day8.github.io/re-frame2/spec/conformance/); the operational walk is [`conformance.md`](conformance.md).

- **Read the corpus at the pin.** An EDN reader is ~200 lines in any host with maps and vectors; or translate the corpus locally at bootstrap.
- **Enumerate, don't transcribe.** Fixture ids, capability tags, handler-DSL ops, Mode-B `:call` ops, and the top-level `:fixture/*` key set are all facts of the corpus at the pin — the greps are in [`conformance.md`](conformance.md).
- **Fail loud on the unknown.** An unrecognised `:fixture/spec-version`, a capability in neither the claim nor the `known-skipped` allowlist, an unknown handler-DSL op, an unknown Mode-B `:call` op, a top-level `:fixture/*` key the harness does not implement, a `known-skipped` entry naming a capability in a v1-required family — each fails the run with a diagnostic naming it, never a silent skip.
- **Grow op-by-op.** Implement handler-DSL and Mode-B operators as live fixtures require them. Do not invent a generated fixture-translation layer or a cross-host compatibility package.

A loop-step-4 slice may report "not run" only while this seam does not yet exist, and the seam lands with the first foundation EP.

## The loop (every EP)

1. **Read the owner at the pin** — the EP row's links below.
2. **Enumerate what applies** — the EP's fixtures, tags, and operators, from the same pin.
3. **Implement the smallest vertical slice.**
4. **Run the narrowest gate that covers it** — the port's unit-test command for the module, or the fixture subset for the EP's tags. Foreground; capture the exact command and result.
5. **Repair, or diagnose** — implementation bug vs spec gap per [`conformance.md` §Diagnosis](conformance.md#diagnosis--spec-gap-vs-implementation-bug); a spec gap goes through cardinal rules 8–9.
6. **Update the port profile** only if a real choice or claim changed.

**Checkpoint** — at whatever granularity fits the work; the contents and the no-mandate rule are in [`SKILL.md` §Checkpoints](../SKILL.md).

**Acceptance gate 1 — the required-foundation gate.** Run every fixture applicable to the four v1-required families — `:core/*` + `:identity/*` + `:flow/*` + `:data-classification/*` (tags expanded at the pin per [`conformance.md` §Capability tagging](conformance.md#capability-tagging)). Never `:core/*` alone — that silently skips the separately-tagged path/identity, flow and classification fixtures the foundation just called mandatory. Nor can the claim be narrowed to make the gate pass: allowlisting a v1-required capability is refused at the harness's required-family floor. A green gate 1 is a **fixture** result: foundation-complete also requires the [live sub-cache witness](#the-ep-006-live-sub-cache-witness-port-owned) below.

### The EP-006 live sub-cache witness (port-owned)

The two `:identity/cedn1` cache-key fixtures (`sub-cache-dedupes-equal-query-v.edn`, `sub-cache-key-map-arg-order.edn`) prove the cache-**key** prerequisite, never the live cache: the corpus subscribes each query once, so a reference-keyed sub-cache passes every required fixture while equal queries create separate derived containers forever and disposal never fires. The owning Spec states the gap ([`spec/006-ReactiveSubstrate.md` §Value-keyed cache-key contract](https://day8.github.io/re-frame2/spec/006-ReactiveSubstrate/#value-keyed-cache-key-contract), conformance-observability note).

So EP-006 carries one **port-owned live test**, required whenever the cache mechanism does not intrinsically key by `rf=`. It runs through the **public/runtime subscription path** — never the canonical-identity primitive — and observes:

1. **One slot from two allocations.** Build `q1` and `q2` as two distinct host allocations of the same query value, prove `rf=(q1, q2)`, subscribe both in one frame: exactly **one** cache-slot creation, one derived container, one shared ref-count.
2. **One lifecycle.** Release one reader — the slot stays live; release the last — the slot is removed and disposal fires **exactly once**.
3. **Negative control.** A third query *not* `rf=` to `q1` creates a **second** cache-slot and a second first-run computation, so a port that interns every query cannot pass degenerately.

Mechanism-agnostic: an `rf=`-keyed persistent map and an interned canonical key both pass — what is required is the observable result, never a library. It reports at the EP-006 checkpoint and at `SKILL.md` §Done, **beside** the score, never inside it. A reference-keyed host is not EP-006-, foundation-, or v1-complete while the witness is red or unrun.

Foundation traps the spec names, owners linked:

- **Flows are v1-required, and "minimum" scopes the API, not the obligation.** [`spec/013-Flows.md`](https://day8.github.io/re-frame2/spec/013-Flows/) restrains flows on purpose — a convenience for a narrow set of problems, never a replacement for subscriptions, and *when in doubt, use a subscription*. Read that restraint as a budget for how much flow surface to build (the **minimum claim** in the Spec's opening block: registered, runtime-toggleable computed-state declarations that materialise into `app-db`, toggled by the two reserved fx-ids), never as permission to skip Spec 013. A port with no `reg-flow`, no lifecycle effects and no flow transform in the drain is not v1-complete, however small its intended app.

- The `[]` root path focuses the whole value: `put(s, [], x) = x`. Delegating `put` to a raw host `assoc-in` is non-conforming ([`spec/Conventions.md`](https://day8.github.io/re-frame2/spec/Conventions/)).
- Durable writes fold recorded `:rf.cofx` facts; re-reading the host clock (or a UUID/random source) inside the fold breaks replay ([`spec/002-Frames.md`](https://day8.github.io/re-frame2/spec/002-Frames/)).
- The effect-map envelope is policed before routing — malformed shapes produce structured errors, never a silent repair ([`spec/Implementor-Checklist.md` §Required](https://day8.github.io/re-frame2/spec/Implementor-Checklist/#required-not-gated-every-implementation-ships-these)).
- Production elision scopes to the dev trace surface only; the always-on substrates ride a separate ungated path ([`spec/009-Instrumentation.md` §Production builds](https://day8.github.io/re-frame2/spec/009-Instrumentation/#production-builds-zero-overhead-zero-code)).
- Frame boundaries have **two ENSURE lifecycle realizations** — the root door ([`spec/004C-Roots-and-Mount.md` §7.1](https://day8.github.io/re-frame2/spec/004C-Roots-and-Mount/)) and the commit-owned two-pass `useLayoutEffect` one ([`spec/002-Frames.md` §frame-root](https://day8.github.io/re-frame2/spec/002-Frames/#frame-root--the-ensure-component-cljs-reference), which states the two-pass contract and then names how each host's React binding realises it). Read the timing rules there; pick whichever the host's render model makes honest, and hold it.

## Cross-cutting obligations (spec-owned; read, don't restate)

- **The uniform async reply envelope** — [`spec/Managed-Effects.md` §The uniform reply envelope](https://day8.github.io/re-frame2/spec/Managed-Effects/#the-uniform-reply-envelope) binds every async family the port claims (HTTP, resources + mutations, machine async work, route loaders). Do not build per-family reply vocabularies.
- **The composition substrate** — `image → frame → event stream` ([`spec/002-Frames.md` §Resolved decisions](https://day8.github.io/re-frame2/spec/002-Frames/#resolved-decisions)): one registrar, `rf/image` / `rf/make-frame`, frame-derived resolution. There is **no realm / app / module composition layer** to build or conformance-check.
- **The view-tagging contract binds every host that renders through a React binding, and no fixture grades it.** [`spec/006-ReactiveSubstrate.md` §View tagging contract](https://day8.github.io/re-frame2/spec/006-ReactiveSubstrate/#view-tagging-contract) makes `data-rf-view="<id>"` on each registered view's rendered root **v1-required** — for the reference adapters and for every cross-compile-language port alike. It is the *only* runtime view-id capture surface there is: a tool resolves a view-id to its rendered root, and an arbitrary node back to its producing view, through this attribute and nothing else. Read the owner for the value format, the mutate-the-first-element's-attribute-map rule (a port MUST NOT wrap the rendered tree in a synthetic host element — that breaks flex/grid parentage, table structure and `:nth-child` counting), the root shapes that are exempt, and the production-elision gate it shares with the source-coord annotation. **The corpus cannot see any of this**: render-time observables are out of scope for a host-agnostic pure-data corpus ([`spec/conformance/README.md` §Render-time observables](https://day8.github.io/re-frame2/spec/conformance/#render-time-observables-out-of-scope)), so both acceptance gates stay green on a port that never stamps the attribute, and a port can be fixture-perfect with every tool-facing surface dark. Like the live sub-cache witness above, it is therefore **self-reported unless the port tests it** — cover it with a host-side test that asserts the attribute on a rendered root; the corpus score cannot speak for it. Hierarchy *over* the tags is a separate question and is explicitly tool-owned and optional — no port owes a walker.
- **Tooling security** — [`spec/Implementor-Checklist.md` §Security obligations](https://day8.github.io/re-frame2/spec/Implementor-Checklist/#security-obligations-for-implementation-tooling) binds any tooling the port ships, the conformance harness included: the env-var write-path allowed-prefix constraint, and `javascript:` / `data:` / `vbscript:` scheme rejection at both registration and click time.
- **Pattern-level security, beyond that tooling subset** — [`spec/Security.md`](https://day8.github.io/re-frame2/spec/Security/), a normative companion whose behavioural MUSTs bind the runtime: [§Behavioural MUSTs across the privacy surface](https://day8.github.io/re-frame2/spec/Security/#behavioural-musts-across-the-privacy-surface), the output / open-redirect / CRLF boundaries, and [§Production gates](https://day8.github.io/re-frame2/spec/Security/#production-gates) — the trace surface and dev-only instrumentation elide in the release build, with [§Which defences survive a production build](https://day8.github.io/re-frame2/spec/Security/#which-defences-survive-a-production-build) naming those that do not.
- **The five-clause runtime-subsystem contract** — [`spec/Runtime-Subsystems.md` §The five-clause contract](https://day8.github.io/re-frame2/spec/Runtime-Subsystems/#the-five-clause-contract): every `:rf.runtime/*` child of the runtime-db partition MUST answer subtree, write authority, read API, projection / elision policy, teardown. Not an optional-capability concern — [`spec/009-Instrumentation.md`](https://day8.github.io/re-frame2/spec/009-Instrumentation/) owns `:rf.runtime/elision`, so a minimum port already ships one graded child and each claimed capability adds its own. A subtree answering fewer clauses is ad-hoc runtime state, outside what tools, hydration projection and the audit assume.
- **The derivation vocabulary** — [`spec/Derivations.md`](https://day8.github.io/re-frame2/spec/Derivations/), also a normative companion: the one vocabulary subscriptions, runtime subscriptions, flows, resources, route facts and machine selectors lower to (declared inputs, output fact, storage class, evaluation policy, lifecycle / owner), plus the node/edge graph model and the whole-value law. It owns the graph the `:derivation/*` fixtures grade through the `:derivation-graph` `:call` op. Slice-1 is vocabulary only — no public authoring primitive to build.
- **Two Spec 011 rules bind a port that never renders server-side** ([`spec/README.md`](https://day8.github.io/re-frame2/spec/README/) Track 3, item 6): [§Frames are per-request](https://day8.github.io/re-frame2/spec/011-SSR/#frames-are-per-request) — a per-request frame is an ordinary Spec 002 frame, so that isolation contract is already built — and [§`:platforms` metadata on `reg-fx`](https://day8.github.io/re-frame2/spec/011-SSR/#platforms-metadata-on-reg-fx), where every effect declares the platforms it runs on (absent ⇒ `#{:server :client}`) and the resolver gates dispatch on it. `:core/*`-only fixtures already carry an fx registration with `:platforms` — `construction-in-handler-guard.edn`, `cross-spec-dispatch-sync-in-handler.edn`.
