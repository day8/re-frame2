# phase-2-impl-order

The EP-by-EP implementation walk for Phase 2. Each section names: what to read first, the contract the port must expose, what the CLJS reference did (**one** worked example, not normative), what the conformance fixtures check, common spec-gap traps. Walking order is dependency-driven — earlier EPs are foundations; do not skip ahead.

**Four cross-cutting anchors to keep open for every EP below:**

- [`spec/Ownership.md`](https://day8.github.io/re-frame2/spec/Ownership/) — the canonical "where does X live" contract-surface map. When an EP touches a surface and you're unsure which spec owns it, this is the index. Read it once before EP 001 and consult it per-EP.
- [`spec/Conventions.md`](https://day8.github.io/re-frame2/spec/Conventions/) — the reserved `:rf/*` single-root namespace scheme, reserved fx-ids, reserved app-db keys, the `reg-*` macro inventory, **the `:rf/path` algebra, and the canonical EDN identity rule (`CEDN-1`)**. Almost every framework id your port emits lands under `:rf/*`; honour the scheme from EP 001 onward (cardinal rule 10). **The one carve-out:** the three reserved fx-ids `:dispatch`, `:dispatch-later`, and `:raise` ship **unqualified** (bare, not under `:rf/*`) — register and recognise them exactly as-is; do not namespace or reject them (per [`cardinal-rules.md` §10](cardinal-rules.md) and [`spec/Conventions.md` §Reserved fx-ids](https://day8.github.io/re-frame2/spec/Conventions/#reserved-fx-ids)). Conformance fixtures assert `:rf.*` operation ids on the trace stream and emit the bare `:dispatch` / `:dispatch-later` fx from handler `:fx`. The same document is the normative home for the **one** path algebra and **one** canonical-identity rule every consumer inherits — see the shared-foundation section directly below (cardinal rule 11).
- [`spec/API.md`](https://day8.github.io/re-frame2/spec/API/) — the consolidated public signature list. Read the relevant entries first whenever an EP's "The contract" names a public surface (`reg-*`, `dispatch`, `subscribe`, the fx/cofx surface, …).
- **[`spec/Conventions.md` §The `:rf/path` algebra / §Canonical EDN identity](https://day8.github.io/re-frame2/spec/Conventions/) — the shared path + identity foundation.** Paths and equality-sensitive identity are a single contract every subsystem (app-db / runtime-db focus, schema paths, redaction-mark paths, flow inputs/outputs, route params, resource keys, work ids) inherits — not a per-feature reinvention. The semantics are normative immediately; the helpers are internal at this slice. Read [§The shared path + identity foundation (EP-0012)](#the-shared-path--identity-foundation-ep-0012) below before EP 002, because the frame/sub/flow/route surfaces all sit on it.
- **[`spec/Derivations.md`](https://day8.github.io/re-frame2/spec/Derivations/) — the derivation/process algebra.** The named-shape family doc that names the **one** view subscriptions, flows, resources, route facts, and machine selectors all lower to (five declared axes: inputs, output, storage class, evaluation policy, lifecycle/owner; two superkinds `:derivation` / `:process`). It is the *vocabulary and inspection contract* analogue of [`spec/Managed-Effects.md`](https://day8.github.io/re-frame2/spec/Managed-Effects/) (effect surfaces) and [`spec/Runtime-Subsystems.md`](https://day8.github.io/re-frame2/spec/Runtime-Subsystems/) (durable-state surfaces). **It mints no new authoring primitive and no public accessor name** — a port that implements subs/flows/resources/routes/machines correctly already satisfies it; the doc only adds a *gradeable shape* the optional internal graph accessor and conformance fixtures read. Because it is gated by the *optional* Tool-Pair inspection surface (not core), its full section lives in the Optional-EPs block — see [§The derivation/process algebra (EP-0014)](#the-derivationprocess-algebra-ep-0014), next to the Tool-Pair attachment surface.

## The shared path + identity foundation (EP-0012)

**re-frame2 has one path algebra and one canonical-identity rule, stated once and inherited everywhere** — by app-db/runtime-db focus, schema paths, redaction-mark paths, flow inputs/outputs, route params, resource cache keys, work ids, and future feature-module declarations. Plain vector paths stay valid and mechanically migratable from re-frame v1; this is the algebra *behind* them. It is **not** a public optics API and **not** a per-subsystem feature. A port that lets flows grow a private `overlap?`, resources a bespoke "stringify the params" cache key, and routing its own canonicalizer ships three subtly-divergent identity rules — exactly the drift this foundation prevents (cardinal rule 11).

**Internal-first.** The reference helpers — conceptually `rf.path/{get,lookup,put,over,compose,prefix?,overlap?,instantiate}` and `rf.identity/{canonical,canonical-bytes}` — are **internal** at this slice: no `re-frame.core` facade export, no facade classification yet. An op graduates to a public name (and gets classified then) only once **two or more** consumers (flows / schemas / routing / resources / frame-config path maps / map-form mutation targets) use it through the internal namespace without forcing a shape change. The *semantics below are normative immediately* — build the foundation from the start because EP 002 frame focus, EP 006 sub composition, EP 013 flows, EP 012 routing, EP 010 schemas, and EP 015 mark paths all stand on it, even though the public surface stays small. **No subsystem may keep a private ad hoc overlap, canonicalization, or path-round-trip implementation once the shared helpers exist.**

**The contract the port must expose.**

- **Concrete path vectors over the shared segment domain.** A concrete `:rf/path` is a **vector** of EDN path segments focusing a value (`[]`, `[:user]`, `[:cart :items 42 :qty]`, `[:rf.runtime/routing :current :params :slug]`). The **segment domain** is the shared portable-EDN upper bound — keywords, strings, symbols, safe-range integers, booleans, UUIDs, instants, and `nil` — **never** functions, atoms, promises, DOM nodes, AbortControllers, or opaque host objects (rejected at the boundary that accepts the path). A spec MAY *narrow* the domain for its surface (flows exclude `nil` output segments; SSR allowlists are single-segment) as a **stated policy over the shared definition**, never a private re-definition. The primary container is a vector; APIs may accept any sequential for migration ergonomics, but **all stored declarations normalize to a vector**.
- **The empty vector `[]` is the root path.** It focuses the entire value. This is the single most common realisation bug: delegating `put` to a raw host `assoc-in` is **non-conforming**, because `(assoc-in {:a 1} [] x)` assocs under the key `nil` instead of replacing the root. The required behaviour is `put(s, [], x) = x` (and `get(s, [], nf) = s`, `over(s, [], f) = f(s)`, `overlap?([], p) = true`). A second realistic violation: a `put` that "optimizes" a `nil` write by `dissoc`-ing breaks the `put`-`lookup` law at `x = nil` — the missing-vs-present-`nil` distinction the algebra deliberately preserves (`(lookup {} [:page])` is `{:present? false}`; `(lookup {:page nil} [:page])` is `{:present? true :value nil}`).
- **The path operations + the path laws.** `get` / `lookup` / `put` / `over` / `compose` / `prefix?` / `overlap?`, satisfying the `put`-`lookup` round trip, `put`-`put` collapse, `compose` units + associativity, and `get`-`compose`. Missing/segment-incompatible intermediates are created as **maps** (matching `assoc-in` / `update-in`); vector indexes are supported only for in-range non-negative integers (an out-of-range or non-integer segment replaces the vector with a fresh map, keeping `put` total).
- **One symmetric `overlap?`.** `overlap?` is true exactly when **either** path is a prefix of the other — `(overlap? [:cart :items] [:cart :items 42])` is `true` (parent/child), `(overlap? [:cart :items 42] [:cart :items 43])` is `false` (siblings), `(overlap? [] [:anything])` is `true`. It is **symmetric**, and it is the relation flows already need (flow B depends on flow A when A's output overlaps a B input; two output paths overlapping in one frame is invalid). **Flows, schemas, and resources MUST use this one shared relation, never a private one.** (Path *templates* need a separate `may-overlap?` relation because variables stand for many concrete values — tooling-only, not required for concrete runtime sorting.)
- **Declaration normalization + the `[:rf.path/param …]` template form.** A named path declaration is a data map reserving **`:rf/path`** for the path slot. A **path template** carries named variables, and the **canonical stored shape** of a variable is the explicit data form **`[:rf.path/param <name>]`** (under the reserved `:rf.path/*` namespace). The `'?name` quote-symbol spelling is **declaration-boundary sugar**, normalized into the data form — **`'?name` never appears in any stored or serialized shape** (one fact, one identity; the data form is what `CEDN-1` encodes and what traces / Xray display). A concrete runtime path that literally contains the symbol `?invoice-id` is just a symbol segment — not substituted unless processed as a template declaration. Instantiation is pure; an unbound parameter **fails closed** (it must not silently produce a `nil` segment).
- **CEDN-1 canonical EDN identity — key order irrelevant, fail-closed, digest derived-only.** Every equality-sensitive runtime identity (resource params and scopes, scoped resource keys, work ids, route path/query params after coercion, named path declarations and templates, schema digest path keys) uses one **canonical identity** function over portable EDN: **equal facts produce the same identity across CLJ/CLJS hosts, and map key order is irrelevant** (`(= (canonical {:page 1 :tag "cljs"}) (canonical {:tag "cljs" :page 1}))`). Canonical identity is **NOT** stringification — `str`, `pr-str` over unordered host maps, `JSON.stringify`, and object identity are not valid identity contracts (host-dependent, insertion-order-leaking, reference-dependent). The canonicalizer **fails closed by default** (`:rf.error/non-edn-identity`) on any out-of-domain value — functions; atoms/refs/volatiles/promises/futures; DOM nodes, React elements, AbortControllers, request handles, timers; arbitrary host objects/class instances; floating-point, ratios, arbitrary-precision decimals, NaN, infinities — and an out-of-domain value buried *anywhere* fails the **whole** identity, never a host-comparison fallback. APIs needing such values encode them to portable EDN first (a host date → an EDN `#inst` instant at the boundary). A **digest is a derived, optional, always-recomputable projection** for size-constrained surfaces (the `:rf.size/include-digests?` flag is the precedent) — **never an independent identity fact, never required for correctness, never the authoritative stored key in v1**; the canonical EDN value **is** the identity everywhere (storage, work ledger, traces, epoch/replay). `CEDN-1` is the reference byte encoding — a type tag before every value, map entries sorted by key bytes, set elements sorted by element bytes; an internal comparison/digest format, not a display or URL format. A port MAY store a normalized projection or a digest, but equality-sensitive comparison MUST be equivalent to comparing `CEDN-1` bytes. The type tag is part of the bytes, so `"42"`, `42`, `:42`, `[1 2]`, and `(1 2)` cannot collide (heterogeneous map keys are legal within the domain), and vectors / lists / sets stay distinct EDN facts.
- **Scoped resource keys + work ids on the one rule.** A **scoped resource key** is `[canonical-scope resource-id canonical-params]`, where scope and params use the shared canonical rule, so map insertion order cannot change the key. **Work ids** build on it (`[:rf.work/resource scoped-resource-key generation]`) — one work record has **one** canonical id; a port MUST NOT carry a second near-duplicate stale-suppression key for the same facts under a different head keyword.
- **Canonical route emission.** Registered route patterns define a lawful partial round trip (a *prism*): `match-url(route-url(...))` returns canonical route data, query keys emit in **deterministic canonical order**, `nil` query values are **elided**, and out-of-domain params **fail closed**. The prism laws are normative, but their **conformance and consumer wiring live in EP 012 routing** (the tier-2 routing consumer slice) — this foundation states only the shared definition routing cites. A future data-form route pattern MUST normalize into the canonical `[:rf.path/param …]` template shape (a second template grammar is the per-subsystem redefinition the algebra prevents).

**Conformance / acceptance note.** There is no dedicated `:path/*` or `:identity/*` conformance family at this slice — the semantics are verified *through* the consumers that cite them (the flow dirty-check + topo-sort fixtures exercise `overlap?`; routing param-change fixtures exercise canonical route data; resource/work identity rides the scoped-key rule). The acceptance signal a port asserts directly is the **laws**: round-trip `put`/`lookup` at `[]` and at `x = nil`; `overlap?` symmetry on parent/child vs siblings; `(canonical m)` invariant under map key reordering; the canonicalizer raising `:rf.error/non-edn-identity` (not host-comparing) on an out-of-domain value; and a template normalizing `'?name` to `[:rf.path/param name]` before storage. Build these as the port's own unit tests when EP 002's path-focus surface first exists.

**Where each EP touches it.** EP 002 — frame focus (`:db` writes, sub queries) and the closed effect-map's path-addressed `:db` are concrete `:rf/path`s; EP 006 — sub/derived composition reads focus through the algebra; EP 010 — schema paths and the schema digest path keys use the canonical rule; EP 015 — frame-config `:sensitive` / `:large` `{:app-db [path…]}` classification paths and registration-metadata `:sensitive` / `:large` paths are concrete `:rf/path`s (frame-config path maps accept concrete paths only — a stated narrowing); EP 013 — flow `:inputs` / `:output-path` outputs use the shared `overlap?` for dirty-check + topo-sort; EP 012 — route params, the prism round trip, and the `[:rf.path/param …]` template form; resources / work ledger — scoped keys + work ids. Wire the foundation once and let every EP consume it.

Per [`spec/Conventions.md` §The `:rf/path` algebra / §Canonical EDN identity / §Canonical byte encoding (`CEDN-1`)](https://day8.github.io/re-frame2/spec/Conventions/); design rationale in [`docs/EP/EP-0012-path-optics-and-canonical-forms.md`](https://day8.github.io/re-frame2/EP/EP-0012-path-optics-and-canonical-forms/).

## EP 001 — Registration

**Read first.** [`spec/001-Registration.md`](https://day8.github.io/re-frame2/spec/001-Registration/). Plus [Implementor-Checklist §F6 Hot-reload primitive](https://day8.github.io/re-frame2/spec/Implementor-Checklist/#f6-hot-reload-primitive) for the re-registration contract, [`spec/Conventions.md`](https://day8.github.io/re-frame2/spec/Conventions/) for the reserved `:rf/*` scheme the registrar must honour, and the `reg-*` entries in [`spec/API.md`](https://day8.github.io/re-frame2/spec/API/) for the public registration signatures.

**The contract.**

- A single registrar — a `(kind, id) → metadata-bearing entry` map. Build exactly **one** registrar, the one source of registrations (see §Composition substrate below). Public registration resolution is **frame-derived**: a frame resolves lookups through its resolved image generation (EP-0023).
- Closed kinds (the canonical set). Always implement the core: `:event`, `:sub`, `:fx`, `:cofx`, `:interceptor`, `:view`, `:frame`. Add the rest only as their optional EP comes into scope — `:route` (Routing 012), `:head` (SSR 011), `:error-projector` (SSR error projection 011), `:flow` (Flows 013), and the **late-bound** `:resource` / `:mutation` / `:resource-scope` (Resources 016, gated by Q10, ride Q9 Managed HTTP). Late-bound = the optional `day8/re-frame2-resources` artefact registers them at load; omit the artefact and no entries of those kinds exist, but the registrar's closed-kind set still admits them. Adding a kind outside the canonical set is a spec change, not a port choice. There is **no** `:machine`, `:machine-action`, or `:machine-guard` kind — a machine registers as an ordinary `:event` entry; its guards/actions are machine-scoped, not registry kinds. `:interceptor` (EP-0022) IS a canonical core kind: the public `reg-interceptor` / `reg-interceptor*` registrar. Event registration is the one `reg-event` form, so application full-context work is a **registered interceptor** referenced by id (bare keyword or `[id arg]`) from an event/frame `:interceptors` chain — never an inline value; the one framework-standard interceptor is `[:rf.interceptor/path <path-vector>]` (per [`spec/001-Registration.md` §Interceptors](https://day8.github.io/re-frame2/spec/001-Registration/#interceptors--reg-interceptor-the-interceptor-registrar)). App-db schemas ([`spec/010-Schemas.md`](https://day8.github.io/re-frame2/spec/010-Schemas/)) are **not** a registrar kind either — they live in the schemas artefact's per-frame side-table. Per [`spec/001-Registration.md` §Registry model](https://day8.github.io/re-frame2/spec/001-Registration/#registry-model--the-canonical-kind-keyword-set), the resource-registrar rows in [`spec/API.md`](https://day8.github.io/re-frame2/spec/API/), and the CLJS reference's closed set in `implementation/core/src/re_frame/registrar.cljc` (`kinds`).
- Public `reg-*` surface — one per kind. Each `reg-*` takes id + metadata + handler-or-spec.
- Registration metadata — `:doc`, source coords (`:ns`/`:line`/`:file` if the host supports source-coord capture), `:tags`, kind-specific keys.
- Hot-reload semantics: re-registration replaces the entry atomically and emits `:rf.registry/handler-replaced`.
- Introspection: `(registrations kind)`, `(handler-meta kind id)` per kind.

**What the CLJS reference did (example).** A single atom holding a nested map: `{:event {:id metadata} :sub {...} ...}`. `reg-*` are macros that capture source coords at compile time. Re-registration is `swap!` on the atom. The macros call into functional `register-*` for advanced cases. None of this is normative — your port's mechanics will differ.

**Conformance fixtures.** `:core/registration` family. Verify: register an event → query handlers → handler-meta returns the registered metadata. Re-register → handler-replaced trace fires. Register conflicting id of same kind → policy per the spec.

**Common spec-gap traps.**

- **Source-coord capture.** Hosts without macros (TS at runtime, OCaml-family) capture source coords from stack frames at `reg-*` call time, or via build-time codegen, or omit. The CLJS reference uses macros — that's a choice, not a requirement. Per [`spec/000-Vision.md` §What the pattern does NOT over-commit to](https://day8.github.io/re-frame2/spec/000-Vision/#what-the-pattern-does-not-over-commit-to).
- **Metadata propagation.** The metadata on a `reg-event` registration must be reachable from the trace events fired during the event's drain. The CLJS reference threads `:doc` and source coords through the dispatch envelope; check that your design surfaces the same.
- **`:machine-action` in the conformance fixtures is NOT a runtime registry kind.** The Mode-B FSM fixtures (`:machine-transition` / `:reg-machine`) use `:machine-action` as a top-level key under `:fixture/registry` / `:fixture/handlers` — a *harness-local* binding for attaching pure transition-action bodies in a frameless fixture (see [`spec/conformance/README.md`](https://day8.github.io/re-frame2/spec/conformance/)). The runtime closed kind set above is unchanged; do not wire `:machine-action` into your registrar or reject the fixture when you encounter it.

## EP 002 — Frames + events + effects + subscriptions

**Read first.** [`spec/002-Frames.md`](https://day8.github.io/re-frame2/spec/002-Frames/) — this is the spec's biggest chapter and most load-bearing. Plan two reads: one for the frame contract, one for the drain semantics. Keep the `reg-event` / `reg-sub` / `reg-fx` / `reg-cofx` / `dispatch` / `subscribe` / `reg-frame` entries in [`spec/API.md`](https://day8.github.io/re-frame2/spec/API/) open for the exact public signatures.

**The contract.**

- **Frame** is a `{frame-state, queue, sub-cache, id}` boundary — an isolated runtime context. Multi-instance (per-test, per-request, per-session, default). `frame-state` is the **two-partition** container value `{:rf.db/app <app-db> :rf.db/runtime <runtime-db>}` — see [EP-0001's two-partition frame contract](#the-two-partition-frame-contract) below; `app-db` and `runtime-db` are read-only derived projections over that one container, not separately-stored cells.
- **Dispatch envelope** is `{event, frame, overrides, trace-id, source, :rf.cofx}` — an open map. `:rf.cofx` is the **flat recordable-coeffect map** the runtime guarantees on every envelope (EP-0010 recording / EP-0017 authoring — see [The world-input contract](#the-world-input-contract-ep-0010) below); the rest are open tooling/routing fields.
- **Event handler contract.** `(app-db, event) → effects-map`. Pure. An **ordinary app handler** returns `{:db <new-app-db>, :fx [[<fx-id> <args>] ...]}` — `:db` replaces only the **app-db** partition. (`:db`'s coeffect/effect value is the app-db projection, NOT the whole frame-state value — see the two-partition note below.)
- **Closed effect-map shape — a *policed* contract.** Three top-level keys: **`#{:db :rf.db/runtime :fx}`**, and each `:fx` entry is a `[fx-id args]` tuple. Per [`spec/Spec-Schemas.md`](https://day8.github.io/re-frame2/spec/Spec-Schemas/) §`:rf/effect-map`. `:db` is the app-db partition write; `:fx` carries everything else; `:rf.db/runtime` is the **runtime-db** partition write, reserved **by convention** for framework / runtime-extension authority — ordinary app handlers return only `:db` + `:fx`. The fx interpreter does NOT trust the handler's return: validate the shape *before* routing (a top-level key **outside `#{:db :rf.db/runtime :fx}`**, a non-sequential `:fx` value, or a malformed `:fx` entry are each dropped-but-continue with an `:rf.error/effect-map-shape` trace; a non-map/non-`nil` return is a no-op with an `:rf.error/effect-handler-bad-return` trace). `:rf.db/runtime` is **NOT** a shape error: an ordinary app handler emitting it is surfaced by a dev diagnostic (`:rf.warning/app-handler-runtime-effect`), not shape-rejected. These never throw — see EP 009's proactive shape-policing note; don't lower a lenient guard that accepts any non-empty entry vector, and don't shape-reject `:rf.db/runtime`.
- **Six-step pipeline.** Per the EP — coeffect assembly → event handler → effects map → fx routing → side-effects → trace. Coeffect assembly delivers the handler's **declared** coeffects (`:rf.cofx/requires`) flat into the coeffects map alongside the fold's own `:db` / `:event` and the framework context keys `:rf.db/runtime` / `:rf.frame/id` (see [The world-input contract](#the-world-input-contract-ep-0010)).
- **Run-to-completion drain.** Per frame; an event's cascade settles before the next event is processed. Async fx schedule and re-enter via `:dispatch`.
- **Subscription system.** Query → value-from-state with stable composition. Layer-1 app subs read the **app-db** projection; layer-1 framework subs read the **runtime-db** projection; layer-2+ compose via `:<-`. Cache invalidates by `=`-equality, **partition-aware** — a runtime-only commit does not invalidate app subs, and an app-only commit does not invalidate framework subs (see the two-partition note below).
- **`reg-frame` is atomic** create-and-register. Frame state (both partitions) is preserved across `reg-frame` re-registration for hot-reload.

#### The two-partition frame contract

**A frame is two partitions (EP-0001).** A frame's durable state is **one physical `frame-state` container value** holding two partitions:

```clojure
{:rf.db/app     <app-db>      ; the application owns this — user data and NOTHING else
 :rf.db/runtime <runtime-db>} ; the framework owns this — machine snapshots, route slice,
                              ;   elision declarations, SSR metadata; addressed by :rf.runtime/* children
```

- **`app-db` and `runtime-db` are read-only derived projections** over that one container (`app-db = (:rf.db/app frame-state)`, `runtime-db = (:rf.db/runtime frame-state)`), not separately-stored cells. This is **pattern contract**, not just one acceptable shape — a port MAY differ only if it preserves the projection-equality semantics (per [`spec/002-Frames.md` §One physical container, two projection reactions](https://day8.github.io/re-frame2/spec/002-Frames/) and [`spec/006-ReactiveSubstrate.md` §Frame-state container and partition projections](https://day8.github.io/re-frame2/spec/006-ReactiveSubstrate/)).
- **Write authority is by convention.** An ordinary `:db` effect replaces **only** app-db; a `:rf.db/runtime` effect replaces **only** runtime-db. The two commit coherently as one atomic frame-state transition when a cascade emits both. Ordinary app code writes only `:db`; `:rf.db/runtime` is reserved for framework / runtime-extension authority (diagnosed via `:rf.warning/app-handler-runtime-effect`, not enforced as a capability — per [`spec/002-Frames.md` §Write authority is by convention](https://day8.github.io/re-frame2/spec/002-Frames/)).
- **Partition-aware invalidation comes free** from projection equality: a runtime-only commit leaves the `app-db` projection `identical?`, so app subs neither recompute nor re-render; an app-only commit is symmetric for framework subs. Restore / hydration / time-travel reinstall the coherent `frame-state` (both partitions together).
- **There is no `:rf/runtime` app-db root.** A stray `:rf/runtime` root in a `:db` effect HARD-ERRORS (`:rf.error/legacy-runtime-root`) at the event-commit boundary. Framework runtime state lives in the runtime-db partition under `:rf.runtime/*`, never under an app-db root. (Do not emit `:rf/runtime` app-db paths.)

#### The world-input contract (EP-0010)

**A causal-world-inputs contract rides the dispatch envelope and the coeffect pipeline (EP-0010 / EP-0017).** re-frame2's core model is a fold: `next-frame-state = transition(prev-frame-state, causal-token)`. That model is only literal when a transition's **durable write** is determined by prior frame-state plus the token being folded. A handler / reducer / writer that reads the host ambiently for a fact — "what time is it?", "give me a UUID", "what URL is the browser on?" — and writes it into durable state produces a value that is correct live but **not replayable**. So the envelope carries a flat `:rf.cofx` map of **recordable coeffects**, delivered to declaring handlers, that brings those host facts into the fold as causal input data. **Durable state folds facts, never reads.** Read [`spec/002-Frames.md` §Recordable coeffects](https://day8.github.io/re-frame2/spec/002-Frames/) + [`spec/001-Registration.md` §Coeffects](https://day8.github.io/re-frame2/spec/001-Registration/) (normative); see also [EP-0010](https://day8.github.io/re-frame2/EP/EP-0010-causal-world-inputs/) / [EP-0017](https://day8.github.io/re-frame2/EP/EP-0017-recordable-coeffects/). **A port that omits this contract ships a determinism hole**: epoch-restore / SSR-hydration / replay diverge on every durable write that read the host ambiently.

The contract the port must expose:

- **`:rf.cofx` is a runtime-guaranteed envelope key.** It is a **flat** EDN map — `fact-name → value`, one fact per owner-qualified key, **no grouping sub-maps** — with one runtime-guaranteed key, the framework's built-in `:rf/time-ms` (wall-clock epoch millis). It MAY carry app- or subsystem-supplied owner-qualified facts (`:rf.route/location`, an app's generated id, recorded random *choices* — not seeds). Tokens carry EDN only — never live host objects. The schema is `:rf.cofx` in [`spec/Spec-Schemas.md`](https://day8.github.io/re-frame2/spec/Spec-Schemas/); it is an optional key of `:rf/dispatch-opts` and a guaranteed key of `:rf/dispatch-envelope`. There is no `:rf.world/inputs` opt — a draft-only name, so passing it earns no dedicated error id; it rides the generic `:rf.warning/unknown-dispatch-opt` warning with a did-you-mean naming `:rf.cofx`. Use `:rf.cofx`.
- **Envelope stamping (the router's job).** When the router builds an envelope it MUST ensure `:rf.cofx` exists with `:rf/time-ms`. Caller omitted it → the router stamps `{:rf/time-ms (now-ms)}`, reading `now-ms` **once at the causal boundary**, never re-read inside a handler / reducer / commit. Caller supplied it → the router **preserves the supplied map verbatim** and fills only `:rf/time-ms` when absent (it never overwrites a supplied value). Supplying it is how tests, replay fixtures, SSR hydration, and host integrations pin exact world facts.
- **Child dispatches stamp FRESH.** A child dispatch from `:dispatch` / `:dispatch-later` is a **distinct causal token** — it gets its own `:rf.cofx` map and MUST NOT inherit the parent's `:rf/time-ms`. So `:rf.cofx` is deliberately **absent** from the cascade's `inheritable-envelope-keys` (contrast `:fx-overrides` / `:interceptor-overrides` / `:trace-id` / `:origin` / `:frame`, which ARE inherited; `:event` and `:source` are not, like `:rf.cofx`). Timer-fire events, HTTP replies, router events, machine timer events, SSR hydration events, and tool-issued events are all envelopes that stamp or supply their own `:rf.cofx`.
- **Stamped UNCONDITIONALLY (prod and dev).** Unlike the dev-only `:dispatch-id` correlation slot (which elides under `goog.DEBUG=false`), `:rf.cofx` is stamped in production too — recordable coeffects are durable causal data a durable write folds, not a diagnostic. Do NOT gate the stamp behind the debug flag.
- **Declared-only, flat delivery.** A handler declares the coeffects it consumes via `:rf.cofx/requires` (a vector of registered coeffect ids; a parameterized id is `[id arg]`); the runtime delivers **exactly the declared leaves**, flat, under their ids — alongside the fold's own `:db` / `:event` and the framework context keys `:rf.db/runtime` / `:rf.frame/id`. An undeclared leaf on the token is **not staged** (no nested `:cofx` / `:rf.cofx` duplicate in the coeffects map; generic code reads the envelope's canonical map through the context). `handler-meta` is the complete consumption record. The COEFFECTS lens shows the declared recordable leaves, filtering the framework-internal context keys.
- **`reg-cofx` is value-returning + graded; there is no `inject-cofx`.** A supplier is `(fn [] value)` or `(fn [arg] value)` returning the value directly. The grade is a registration property: **ambient** (default — runs at context assembly, never recorded, replay re-runs it; legal only where no durable write depends on it) or **recordable** (`:recordable? true` — ensured onto the token, recorded, re-presented verbatim by replay; a `:provided? true` recordable fact has no generator, its owner stamps it). Calling `inject-cofx` is the hard error `:rf.error/inject-cofx-removed`. The port's replay/restore path must re-present captured recordable values rather than re-invoke the supplier.
- **There is no `:dispatched-at` envelope field.** The *durable* causal-time fact is `(:rf/time-ms (:rf.cofx envelope))`; the *diagnostic* dispatch-time need is the trace event's own ambient `:time` stamp (Spec 009). A port must not emit or recognise `:dispatched-at`.

**Conformance / acceptance note.** The recordable-coeffect contract is core, not an optional EP. A conforming port: stamps `:rf.cofx` `:rf/time-ms` on every envelope; preserves a caller-supplied map verbatim; stamps children fresh (no `:rf/time-ms` inheritance); delivers a handler's declared coeffects flat (declared-only); registers `reg-cofx` as a value-returning graded supplier and hard-errors on `inject-cofx`; re-presents recordable values on replay rather than re-running suppliers; and emits no `:dispatched-at`. Replay/restore determinism for durable writes is the observable acceptance signal — assert that restoring an epoch (or replaying a recorded token) reproduces the same `:created-at`/`:updated-at`/id values rather than re-reading a moved clock.

**What the CLJS reference did (example).** A frame is a deftype holding **one** `r/atom` (Reagent ratom) for the `frame-state` value plus mutable fields for the queue and sub-cache; `app-db` and `runtime-db` are projection reactions (`r/reaction`) layered over that one container. Dispatch drains via a synchronous loop that flushes after each event. Subscriptions are Reagent reactions cached in the sub-cache; the partition projections give equality-invalidation for free. The reference uses an interceptor **chain** — chained transforms over the dispatch envelope — as the implementation strategy for the six-step pipeline; that *chain-as-pipeline-execution mechanism* is an implementation detail (per [`spec/Cross-Spec-Interactions.md`](https://day8.github.io/re-frame2/spec/Cross-Spec-Interactions/) a port may use a monad / coroutine / state machine over the dispatch envelope instead). **Registered interceptors themselves, however, ARE a public contract** (`reg-interceptor`, EP-0022 — see EP 001): application full-context work is routed to interceptors, so a port must expose them as an authoring surface, referenced by id from `:interceptors` chains. The one-container + two-projection shape is pattern-required; the Reagent realisation of it is not.

**Conformance fixtures.** `:core/event-handler`, `:core/sub`, `:core/fx`, `:core/frame`, `:core/drain`, `:core/trace`. Verify: dispatch increments a counter → app-db updates; subs over the counter return the new value; `:dispatch` fx re-enters; the drain settles before the next external dispatch.

**Common spec-gap traps.**

- **Closed effect-map shape.** The closed top-level set is **`#{:db :rf.db/runtime :fx}`**. App-level effects do NOT go in `:db` or `:fx` peer position — they go inside `:fx`. The one framework-reserved peer is `:rf.db/runtime` (the runtime-db partition write); ordinary app handlers emit only `:db` + `:fx`, and a port must **diagnose, not shape-reject**, an app handler that emits `:rf.db/runtime` (`:rf.warning/app-handler-runtime-effect`). Your port enforces the closed-shape rule from the start. Per [`spec/002-Frames.md`](https://day8.github.io/re-frame2/spec/002-Frames/) and [`spec/Spec-Schemas.md` §`:rf/effect-map`](https://day8.github.io/re-frame2/spec/Spec-Schemas/#rfeffect-map).
- **Run-to-completion vs sync vs async fx.** Sync fx run inline; async fx schedule via host's promise/timeout and re-enter through `:dispatch` after the side effect completes. Async fx must NOT call back into the runtime during the current drain — that would violate run-to-completion.
- **Sub cache invalidation.** The cache invalidates by value equality on inputs. Identity-only equality (`===` in JS without deep compare; reference equality in general) breaks the contract. Your persistent data structure choice (F2) must provide cheap value-equality.
- **Frame revertibility.** The frame's full state — the whole `frame-state` value (`{:rf.db/app … :rf.db/runtime …}`), both partitions together, plus any per-frame registry tier — must be revertible by one value swap. Restore / hydration / time-travel reinstall a coherent frame-state, never one partition in isolation. This propagates the F2 (persistent data structures) requirement.
- **Ambient host reads at the durable-write site (EP-0010 recording / EP-0017 authoring).** The single most common recordable-coeffect miss: stamping the envelope's `:rf/time-ms` correctly but still letting a handler / reducer / work-ledger writer re-read `now-ms` (or `Math.random` / a UUID generator / the browser location) *inside the fold* and write THAT into durable state. The stamp is pointless if the write site doesn't declare + read it. Two further traps: (a) **inheriting `:rf/time-ms` into child dispatches** — a child token must stamp fresh, so tying child coeffects to the parent silently breaks per-token determinism; and (b) **staging undeclared leaves** — delivery is declared-only: only the handler's `:rf.cofx/requires` leaves are staged (the framework context keys `:db`/`:event`/`:rf.db/runtime`/`:rf.frame/id` are the fold's own + framework keys, not declarable cofx), and the COEFFECTS lens shows the declared recordable leaves, or every event appears to consume a coeffect it never declared. Audit the recordable-coeffect contract above against the port from the moment EP 002's coeffect pipeline exists.
- **The frame-focus surface IS the shared path algebra (EP-0012).** A `:db` write addressed by a path and a sub query that focuses into app-db are both concrete `:rf/path`s over the [shared segment domain](#the-shared-path--identity-foundation-ep-0012) — not a frame-private helper. The first time EP 002 needs a `put`/`get` at a path, build the shared `rf.path/*` semantics (root-path law, `overlap?` symmetry, the path laws) rather than reaching for raw `assoc-in` (which violates the root-path law at `[]`). Same for any cache key the sub-cache or a resource derives: route it through the one canonical-identity rule, never `JSON.stringify` / `pr-str` over an unordered map. See [§The shared path + identity foundation (EP-0012)](#the-shared-path--identity-foundation-ep-0012).

## EP 006 — Reactive substrate

**Read first.** [`spec/006-ReactiveSubstrate.md`](https://day8.github.io/re-frame2/spec/006-ReactiveSubstrate/). All ~990 lines — this EP is the load-bearing contract between the runtime and the view layer.

**The contract.** Ten entries total — verbatim from [`spec/006-ReactiveSubstrate.md` §The adapter API contract](https://day8.github.io/re-frame2/spec/006-ReactiveSubstrate/#the-adapter-api-contract). The function set is **closed for v1**.

- **Six required functions** the adapter must provide:
  - `make-state-container` — create a reactive container holding an `app-db` value.
  - `read-container` — read the current value (pure).
  - `replace-container!` — mutate the container with a new value (the only mutation primitive; invalidation rides this).
  - `make-derived-value` — construct a derived (memoised) container from one or more sources.
  - `render` — render a render-tree onto the substrate's surface; return an unmount fn.
  - `render-to-string` — pure render to an HTML string. **JVM-runnable and required even for Q3=no (no-SSR) ports** — do not treat it as optional.
- **Three optional functions** (the core falls back, or no-ops, when absent):
  - `subscribe-container` — register a change-listener for invalidation. Fallback: core runs invalidation inline within `replace-container!`.
  - `register-context-provider` — return a context-provider component that scopes a frame to a subtree. Fallback: explicit-frame-as-argument threaded by the user's view code.
  - `flush-render!` — synchronously commit the substrate's pending renders to the surface (NOT a `requestAnimationFrame`-style tick), so headless tooling can drive a `dispatch → flush-render! → observe-settled-DOM` loop deterministically. Fallback: core no-ops (an adapter that renders without a live commit — plain-atom / SSR — has nothing to flush).
- **One lifecycle slot:** `:dispose-adapter!` — the adapter-spec map key the adapter implements: tear down, release listeners, caches, host resources. This is an **internal adapter-contract slot**, not a public function. (Lifecycle wiring is the core's public `install-adapter!` / `destroy-adapter!` pair — `install-adapter!` binds the adapter at boot, `destroy-adapter!` is the public teardown verb that calls the adapter's `:dispose-adapter!` slot. Neither is part of the adapter's own surface; there is no "start" function.)
- **Single adapter at boot.** A process binds one adapter at boot via `install-adapter!` — the boot-bound adapter selection. There is no realm/container layer wrapping it and no "multi-adapter coexistence is N realms" model; image assembly plus frame isolation are the whole composition story (see §Composition substrate below).
- **Revertibility constraint on adapters.** Adapter-internal state must be derivable from the frame value. No "shadow state" inside the adapter that the frame value can't reproduce on revert. Per [`spec/006-ReactiveSubstrate.md` §Revertibility constraints on adapters](https://day8.github.io/re-frame2/spec/006-ReactiveSubstrate/#revertibility-constraints-on-adapters).
- **Subscription cache invalidation contract.** Per [`spec/006-ReactiveSubstrate.md` §Subscription cache — contract and operational semantics](https://day8.github.io/re-frame2/spec/006-ReactiveSubstrate/#subscription-cache--contract-and-operational-semantics).

**What the CLJS reference did (example).** The substrate contract lives inside core (`implementation/core/src/re_frame/substrate/`): `adapter.cljc` defines the contract, `plain_atom.cljc` provides a dependency-free reference substrate (a plain-atom signal graph, used for JVM / non-browser / SSR paths). On top of that, the React-binding adapters ship as sibling artefacts under `implementation/adapters/` — `reagent`, `reagent-slim`, `uix`, `helix` (plus `test-react` for the test harness). The Reagent-family adapters use Reagent's reaction primitive for subs and hook mount/unmount into React's component lifecycle; the in-core plain-atom substrate uses a hand-rolled signal graph. None of this layout is normative — the split between an in-core reference substrate and per-binding adapters is one worked example.

**Conformance fixtures.** `:core/substrate` family. Verify: replace-container fires the invalidation hook; subscription cache evicts on input change; revert by container swap restores prior view state.

**Common spec-gap traps.**

- **Revertibility constraint.** Easy to violate inadvertently by stashing per-component state in the adapter that the frame can't reproduce. Audit every adapter-internal cache during EP 006 against the constraint.
- **Render-trigger semantics.** The trigger must be observably equivalent to "change in `app-db` → recompute affected subs → re-render dependent views". Your host's React binding must plug subscription reads into React's render cycle (Reagent's auto-tracking; UIx / Helix `use-subscribe` over `useSyncExternalStore`) — not subvert it.
- **Sub lifecycle.** When a view stops reading a sub, the sub should eventually dispose. The mechanism is substrate-dependent (Reagent uses last-deref-disposes-after-a-delay); pick a policy and document it.

## EP 004 — Views

**Read first.** [`spec/004-Views.md`](https://day8.github.io/re-frame2/spec/004-Views/).

**The contract.**

- **`reg-view`** registers a view with the registrar. Public surface for declarative view registration.
- **Pure `(state, props) → render-tree`.** Views are pure functions of their inputs.
- **Render-tree is serialisable data.** Not opaque host objects with closures. The render-tree must serialise for SSR + view-tree tooling.
- **Frame provider (EP-0024, one config-shaped boundary).** Views run in the context of an explicitly-established frame, supplied by `frame-provider`: its `{:frame …}` SCOPE-only shape scopes an already-created frame into a React subtree, while its `{:id …}` ENSURE shape creates-if-absent / reuses-no-reseed / provides a named frame (no destroy-on-unmount); there is no ambient default (EP-0002). A `reg-view` reads the surrounding provider's frame via React context; a view rendered with no provider in scope has no frame and its ambient `dispatch`/`subscribe` raise `:rf.error/no-frame-context`. The port realises both config shapes per substrate against the shared contract. Per [`spec/004-Views.md`](https://day8.github.io/re-frame2/spec/004-Views/) §Frame propagation and [`spec/002-Frames.md`](https://day8.github.io/re-frame2/spec/002-Frames/) §the `frame-provider`.
- **Source-coord stamping.** Where the host supports it, registered views carry source coords for tooling.

**What the CLJS reference did (example).** `reg-view` is a macro that captures source coords, returns a Reagent component, and registers the metadata. Render-tree is hiccup. Frame propagation uses Reagent's component context. Substrate-specific.

**Conformance fixtures.** `:core/view` family. Verify: a registered view reads a sub → mounts → updates when the sub's input changes; the render-tree of a known view matches an expected serialisable shape.

**Common spec-gap traps.**

- **Closed component trees.** A render-tree that includes raw substrate elements with closures (e.g. raw React elements with `useState`) is not serialisable, and breaks SSR + tooling. Keep the render-tree pure data; let the substrate adapter realise it.
- **Frame propagation.** Views rendered under a non-default frame is a common need (test fixtures, story workspaces, embedded sub-apps). Every in-scope host targets React, so the propagation mechanism is React context (the host's React binding supplies the provider); explicit-frame-id remains the underlying contract.

## EP 009 — Instrumentation

**Read first.** [`spec/009-Instrumentation.md`](https://day8.github.io/re-frame2/spec/009-Instrumentation/).

**The contract.** EP 009 has **two distinct surfaces with opposite production postures** — conflating them is the single most expensive 009 mistake (see the trap below). Read [`spec/009-Instrumentation.md` §The three always-on substrates](https://day8.github.io/re-frame2/spec/009-Instrumentation/) and §What is available in production before designing the emit path.

- **Dev-only trace surface (production-ELIDED).** The full structured trace stream — `register-listener!` / `unregister-listener!`, the rich per-emit trace events (event-handler entry/exit, fx invocations, sub computations, the dev-only `:rf.event/*` enrichments), and the retain-N ring buffer — is **dev-only by construction**. Synchronous, in-order, per-emit listener invocation. It DCEs out entirely in a default production build (no listener, no allocation, no overhead). Xray / Story / re-frame-10x consume it in dev. This is what "production elision" governs.
- **Always-on emit surfaces (production-SURVIVABLE).** Two substrates **survive `:advanced` + `goog.DEBUG=false`** and are NOT part of the dev trace surface — they exist precisely for the production / SSR observability posture and would defeat their purpose if a debug-gate flip silenced them. **The public facade reaches both through ONE stream-parameterized listener verb** — `register-listener! stream id f` / `unregister-listener! stream id` / `clear-listeners! stream`, with the closed stream vocabulary `:trace` / `:events` / `:errors` / `:epoch` (an unknown stream throws `:rf.error/unknown-listener-stream`; no bare-trace default, no aliases). There are no `register-(event|error)-listener!` facade functions — those bare names are internal namespace functions only (`re-frame.event-emit` / `re-frame.error-emit`), addressed by internal consumers (router fan-out, the SSR error projector), never on the public facade. **And the normal off-box production path is a *different* verb again** — the frame-owned `:observability` sink (`register-observability-sink!`, D5b / EP 015) — so the two listener streams below are the ADVANCED corpus-wide hook, NOT the off-box default:
  - **`:events` stream — the always-on event-emit listener.** Fires one tight, fixed-shape event-record per processed event (`{:event :event-id :frame :time :outcome :elapsed-ms}`), fanned across EVERY frame with the `:event` slot wire-elided (large → `:rf.size/large-elided`, sensitive → `:rf/redacted`) but otherwise UNPROJECTED — not routed under any frame's egress policy. An advanced cross-frame integration hook; the off-box default is the frame `:observability` sink.
  - **`:errors` stream — the always-on error-emit listener.** Fires one error-record per `:rf.error/*` cascade error (handler / coeffect / interceptor / flow-eval exceptions, fx errors), fanned across EVERY frame with `:event` wire-elided but the `:exception` riding RAW under no frame egress policy. It MUST keep firing post-elision. This is the **advanced** corpus-wide hook for a cross-frame raw-throwable post-mortem shipper; the normal off-box error-reporting path (Sentry / Rollbar / hosted monitors) and the SSR fail-closed status path is the frame-owned `:observability :errors` sink, which hands the sink an already-PROJECTED record. Recovery is the framework's typed per-category default; there is no app-steering recovery policy.
  - Both streams deliver **identical record shapes in dev and prod**, run post-elision (marked values already substituted), and **isolate per-listener exceptions** (one listener throwing must not abort the cascade or the other listeners).
- **Error contract.** Structured records for runtime failures — handler exceptions, schema validation, drain depth, no-such-handler. `:operation :rf.error/<category>`, `:op-type :error`. The same `:rf.error/*` event flows on BOTH surfaces: the dev trace stream (when the gate is true) AND the always-on error-emit substrate (always).
- **Production elision applies to the dev trace surface only.** Every dev trace emit site, the `register-listener!` registry, the ring buffer, and the perf bridge elide in production builds. Mechanism is host-discretion (Closure DCE for CLJS; Vite `define` + tree-shake for JS/TS and Squint; `#if !DEBUG` + tree-shake for Fable; link-time-`if` for Scala.js; release-variant module omission for Kotlin/JS). **The two always-on substrates above are explicitly OUT of the elision scope** — they must survive the same production build that DCEs the trace surface, or hosted observability and error reporting silently vanish.

**What the CLJS reference did (example).** The public `register-listener!` verb dispatches on `stream`: `:trace` to a dev-only listener registry (walked inline behind the `re-frame.interop/debug-enabled?` gate, with a separate ring-buffer atom holding the dev-only history), and `:events` / `:errors` to the internal `re-frame.event-emit` / `re-frame.error-emit` registries which ride a *separate*, ungated emit path that survives `:advanced` + `goog.DEBUG=false`. Dev-trace production elision via `goog-define` + Closure DCE; a CI script verifies dev-only sentinel strings are absent from production bundles — while asserting the always-on substrates remain present.

**Conformance fixtures.** `:core/trace`, `:core/error` families. Verify: dispatching an event emits the expected trace sequence; a handler that throws produces an `:rf.error/handler-exception` trace event; the ring buffer holds the last N events when no listener was registered at emit time.

**Common spec-gap traps.**

- **Listener invocation order.** The spec says "synchronous, in-order, event-at-a-time, exactly once per registered listener". It does NOT specify which listener fires first when multiple are registered. Don't over-commit; don't rely on order in your tests.
- **Production elision — scope it to the DEV TRACE surface only.** The single most expensive 009 mistake is DCE-ing the whole instrumentation module, taking the always-on event/error-emit substrates with it. The `:events` / `:errors` substrates (reached publicly via `register-listener!`, internally `re-frame.event-emit` / `re-frame.error-emit`) **must survive `:advanced` + `goog.DEBUG=false`** — a production build that elides them kills the always-on observation streams, kills production error reporting (and, transitively, the frame `:observability` sinks built on top — the SSR fail-closed status path). Wire the `:trace` stream behind the debug gate; wire the `:events` / `:errors` substrates on a separate, ungated path. The CLJS reference's CI verifier (sentinel-string scan) is a useful pattern to copy — emit a known string at every *dev-only* call site, scan production bundles for any occurrence, fail the build if found — but pair it with a positive assertion that the always-on substrates are still present in the production bundle, so an over-aggressive DCE pass is caught.
- **Error category coverage.** Don't miss categories — and don't assume "category" means "exception." The spec's `:rf.error/*` taxonomy splits into two kinds, and a port that audits only the first ships silent bugs:
  - **Exception-driven (you `catch`).** Every catch must fire a trace event, no silent swallow: `:rf.error/handler-exception`, `:rf.error/fx-handler-exception`, `:rf.error/sub-exception`, `:rf.error/schema-validation-failure`, `:rf.error/drain-depth-exceeded`, `:rf.error/no-such-handler`, and more (spec/009 enumerates ~90 `:rf.error/*` categories; this is a sample, not the whole list). Use the fully-qualified `:rf.error/` form — a bare `fx-exception` is not a category (the real one is `:rf.error/fx-handler-exception`), and consumers/fixtures match on the exact keyword.
  - **Proactive shape-policing (you POLICE, nothing throws).** Two load-bearing fail-closed categories never raise an exception, so "audit each catch" misses them entirely — you must validate the effect-map shape *before* the fx interpreter runs:
    - `:rf.error/effect-map-shape` — a malformed effect-map from a `reg-event` handler (per spec/009 §Error contract, three cases: (a) a top-level key **outside the closed set `#{:db :rf.db/runtime :fx}`**; (b) a non-`nil`, non-sequential `:fx` value, e.g. `{:fx :oops}`; (c) a single `:fx` entry that is not a `[fx-id args]` tuple, e.g. `{:fx [[:good a] :oops]}`). Recovery is `:logged-and-skipped` — one trace per offending key/value/entry, the offender is **dropped while sibling `:fx` entries still run** (a `nil`/empty entry is the legal conditional-fx no-op, NOT traced). **`:rf.db/runtime` is inside the closed set — it is NOT a shape error.** An ordinary app handler that emits it is surfaced by the dev diagnostic `:rf.warning/app-handler-runtime-effect` (a by-convention nudge, not a drop): police it as a *warning*, never as `:rf.error/effect-map-shape`. The `:fx` entry shape is `[:vector [:tuple :keyword :any]]` per [`spec/Spec-Schemas.md` §`:rf/effect-map`](https://day8.github.io/re-frame2/spec/Spec-Schemas/#rfeffect-map).
    - `:rf.error/effect-handler-bad-return` — a `reg-event` handler that returns a value that is neither a map nor `nil`; the dispatch is a no-op + trace (`nil` stays the legal no-op).
  Audit each catch **AND each proactive shape gate** in your port against the spec/009 error contract. A lenient fx-entry guard that accepts any non-empty vector — instead of policing the `[fx-id args]` tuple shape — silently truncates malformed effect maps with no diagnostic (a real bug class). The conformance corpus **backstops this class** (`effect-map-shape-bad-top-level-key.edn`, `effect-map-shape-bad-fx-value.edn`, `effect-map-shape-bad-fx-entry.edn`, `effect-map-shape-surplus-entry-field.edn`, `effect-handler-bad-return.edn`), so a lenient port FAILS conformance here rather than shipping the bug undetected. Still police it from the spec first — the corpus confirms, it does not teach.

## EP 015 — Data Classification (Sensitive + Large)

**v1-required, not optional.** Spec 015 marks itself v1-required. A port that ships 001–009 but omits 015 ships a privacy hole: classified values leak through every observation surface (trace bus, the always-on observability sink records, Xray, MCP wire, third-party log sinks). It lands here — right after 009 — because the classification machinery is a leak-prevention overlay on the 009 emission boundary, so it needs 009's emit path in place first.

**Read first.** [`spec/015-Data-Classification.md`](https://day8.github.io/re-frame2/spec/015-Data-Classification/) end-to-end. Keep open: the `project-egress` / `elide-wire-value` / `register-observability-sink!` entries in [`spec/API.md`](https://day8.github.io/re-frame2/spec/API/) (none of `add-marks` / `set-marks`, a frame `:sensitive {:app-db …}` annotation, `redact-interceptor`, `declare-sensitive-*`, or value propagation is public), [`spec/Conventions.md` §Reserved namespaces / §Reserved commit-plane classification effects](https://day8.github.io/re-frame2/spec/Conventions/) (the four effects, the `:rf.runtime/elision` registry, the `:rf/redacted` / `:rf/large` sentinels are framework-reserved), and [`spec/009-Instrumentation.md`](https://day8.github.io/re-frame2/spec/009-Instrumentation/) §The trace event model (where emission-time substitution hooks in). Per EP-0025.

**The contract.**

- **Opt-in, path-based, fail-open, two parallel axes.** Nothing is auto-detected. The author declares classification as `:sensitive` and/or `:large` over *paths* on *whoever owns the data's shape* — one declaration surface per owner. The contract is **fail-open**: a path you never classify ships raw (hygiene, not a guarantee). The two axes are independent and compose; **sensitive wins over large** on a both-marked path (no size marker that would leak path / bytes / digest).
- **Four declaration surfaces:**
  - **Commit-plane effects — durable app-db.** A handler returns `:sensitive` / `:large` / `:clear-sensitive` / `:clear-large` (each a vector of `:rf/path` vectors, EP-0012) **alongside `:db`**; the runtime folds them into the per-frame elision registry `[:rf.runtime/elision …]` at the **commit point** (NOT a post-commit `:fx`), `:source :effect`. Known paths in the frame's init event (via `:initial-events`), discovered ones in the writing handler. Value-independent; axes clear independently; a malformed payload **fails loud pre-commit** (`:rf.error/classification-effect-shape`, no `:db` commit). There is **no** frame `:sensitive {:app-db …}` annotation (rejected fail-loud), **no** schema-prop route to durable app-db, **no** imperative `add-marks` / `set-marks` / `clear-app-db-marks!` API, and **no** per-process `declare-sensitive-header!` / `declare-sensitive-query-param!` API — the four commit-plane effects are the one route.
  - **Subsystem definition — projection-relative.** Machine `:data` and resource `:data` / params classify via top-level `:sensitive` / `:large` keys on the `reg-machine` / `reg-resource` **definition**, projection-relative to one instance's shape (e.g. `[:data :token]`), lowered per instance at spawn/fetch and dropped on teardown; a malformed declaration fails loud at registration. Machine `:data` SNAPSHOT egress is this declaration; the machine's `[:schemas :data]` `:sensitive?` prop drives only the schema's own validation-FAILURE-trace redaction, not snapshot egress. The machine data-context schema is declared at `[:schemas :data]` (there is no `:data-schema` shorthand key — EP-0029). `reg-machine` is `(reg-machine machine-id machine-spec)` / `(reg-machine machine-id opts machine-spec)`; the `:sensitive` / `:large` keys ride the machine-spec map (the `opts` map carries the event-vector `:schema`).
  - **Schema props — transient products only.** An HTTP request's decoded body classifies via `:sensitive?` / `:large?` Malli props on its `:decode` schema; the same props on a machine's `[:schemas :data]` (and a resource's `:data-schema` / `:params-schema`) drive only validation-FAILURE-trace redaction. Schemas own *transient* and *validation-failure* products, never durable state.
  - **Registration metadata — transient payloads.** `reg-event` (the one public event registrar, EP-0018), `reg-sub`, `reg-fx`, `reg-cofx`, `reg-flow` accept `{:sensitive [path…] :large [path…]}` on their registration map. Paths index into that registration's primary shape — the event arg-map (second element of `[:event-id {arg-map}]`), the fx-input map, the cofx value, the sub output, the flow output; `[[]]` marks the whole shape. A mark at a missing slot is a silent no-op (tolerate shape evolution); a malformed path *vector* fails at registration.
- **Classification does NOT propagate.** There is no input→output inheritance through subs/flows, no value-match/taint engine, and no `:rf.egress/output-sensitivity` declassification claim (silently ignored if present). A derived secret is classified by classifying the OUTPUT path directly (a sensitive flow output is just a classified db path); a re-keyed/unclassified path ships RAW. Arbitrary handler-body provenance is not tracked.
- **One boundary projection — `project-egress` — keep the wire marker and the display sentinel distinct.** Real egress surfaces emit **records** (handled-event records, error records, epoch snapshots, MCP/tool reads), not bare values. `project-egress` is the required, public, record-level boundary primitive: it dispatches on a record's `:kind` (the `:rf.observe/*` kinds) to a **private** per-kind projector and delegates tree-shaped slots to the low-level `elide-wire-value` walker. It takes an `:rf.egress/profile` from a **closed six-member enum** (`:rf.egress/off-box-observability` / `off-box-tool` / `local-redacted` / `local-raw` / `ssr-hydration` / `public-error`), each resolving to a `:rf.size/*` opt-set (an explicit `:rf.size/*` boolean composes on top; the override wins). Two layered vocabularies, NOT interchangeable — a port that emits the wrong one breaks tool consumers:
  - **Wire marker (Spec 009 §Size elision).** What `elide-wire-value` substitutes for a large value at *every off-box egress*. The marker is **`:rf.size/large-elided {:bytes N :head "…" :handle [:rf.elision/at <path>]}`** (sensitive substitutes to `:rf/redacted`). This is the shape MCP / Xray / log consumers parse and the shape the `:elided-large` count and the `[:rf.elision/at …]` re-fetch handle key off — emit anything else and the fetch-handle / counting semantics are lost.
  - **Display sentinel (Spec 015 §The display contract).** What a tool *renders* for a large value: `:rf/large {:bytes N :head "…"}` (large-only — MAY surface a size-confirmed click-to-expand), `:rf/redacted` (sensitive — opaque, MUST NOT be revealable), `:rf/redacted {:bytes N}` (both — size visible, content not, no `:head`). All keywords are framework-reserved; apps MUST NOT use them as payload values. This is a presentation contract for the panel, layered on top of the wire marker — it does not replace what the walker puts on the wire.
- **Substitution happens at PROJECTION time, never mid-handler.** Real values flow through events → cofx → handler → fx → app-db → subs → views **unchanged** — handlers, sub-fns, fx-handlers ALWAYS see real values. The framework substitutes the wire marker only at the boundaries that MUST guard: (1) trace-bus emit, (2) Xray / Story panel rendering, (3) MCP / tool wire transport, (4) AI/LLM context handed off by tools, (5) hosted log sinks. Route every off-box record through `project-egress` (which runs `elide-wire-value` under the owning frame's classification + the chosen profile) — the **same projection the always-on observability sinks consume** (sinks receive already-projected records; no sink-local redaction), so production observability records are also classification-respecting.
- **Frame-owned observability + fail-closed.** Production observability (Datadog / Sentry / Honeycomb) routes through the frame's `:observability` policy: `{:handled-events [{:sink <id> :rf.egress/profile … :opts {…}}] :errors [...]}`, with the concrete sink fn registered via `register-observability-sink!` (always-on — survives `:advanced` + `goog.DEBUG=false`; a throwing sink is isolated from its siblings). Routing and projection are **fail-closed**: an unresolved frame, a frame with no `:observability` policy, or a projection needing frame policy with no frame known routes / redacts rather than leaks — the runtime never synthesizes `:rf/default` and never borrows another frame's policy (EP-0002's no-default-frame rule).
- **No runtime cost on the happy path.** Classification lookups happen only at projection time. The trace-bus emit path is compile-time elided in production per [009 §Production elision] — but the always-on observability sinks still run `project-egress` in production, so production records never leak a classified value either.

**What the CLJS reference did (example).** Frame classification installs into a per-frame registry as part of frame creation (the reserved `[:rf.runtime/elision]` runtime-db child holds the `:sensitive`/`:large` app-db declarations under `:source :frame`); schema props are extracted at registration. Propagation is computed as a path-graph union at projection time (the spec also permits write-time taint-tracking — both conform). `project-egress` lives in `re-frame.projection`, delegating to `re-frame.elision/elide-wire-value`; the trace-bus emit path rides the `goog.DEBUG` gate, the always-on observability sinks run the projection unconditionally. None of this layout is normative.

**Conformance fixtures.** Data-classification fixtures assert that a classified path is elided to the correct **wire marker** at the projection boundary while the real value still flows through the runtime. Verify: a handler returning `:sensitive [[:auth :token]]` alongside `:db` projects `:rf/redacted` at that path in any off-box record but the real value in the handler; a handler returning `:large [[…]]` projects the wire marker `:rf.size/large-elided {:bytes N …}` (the `:rf/large {:bytes N :head}` form is the Xray/display *rendering*, not what the walker writes); `:clear-sensitive` / `:clear-large` clear axis-independently; a malformed effect payload fails loud pre-commit (no `:db` commit); a machine declaring `:sensitive [[:data :token]]` on its `reg-machine` spec redacts that slot in `:rf.machine/*` snapshot trace slots (lowered per actor instance); a re-keyed/unclassified value ships RAW (fail-open — no propagation, no value-match); an unknown profile raises `:rf.error/unknown-egress-profile`; a frameless projection fails closed (redacts) rather than leaks.

**Common spec-gap traps.**

- **Redacting mid-handler.** The framework must NOT redact before the handler runs — handlers need real values. Substitution is projection-time only.
- **Forgetting a consumer.** All off-box records must route through `project-egress`. A port that guards the trace bus but not the always-on observability sinks, the MCP wire, or a log-sink listener still leaks. One boundary primitive; route every observer through it.
- **A second route to classify the same shape.** Schemas describe shape — they are NOT a second route to classify a durable app-db path the frame already owns (schema-attached app-db `:sensitive?` / `:large?` is not part of the public model). One owner, one route. (Per-slot props are the *one* route for the owners whose natural declaration surface IS a schema — machine `:data`, resource data/params, HTTP bodies.)
- **Open-frame default.** Egress is frame-scoped: a projection that can't resolve a frame must fail closed, never synthesize `:rf/default`.
- **Treating 015 as optional.** It is v1-required. Do not gate it behind a D3 question.

### Managed async reply envelope (Property 9 — cross-family obligation, EP-0011)

> **Cross-cutting, not per-EP.** This is **Managed-Effects property 9** — the one async-only property — and it binds *every* managed async family a port claims: HTTP (014), resources + mutations (016), machine async work (005), and route loaders (012). It is **not** a Q-gated EP of its own; if a port implements any async-completing family, it owes this obligation across all of them. Do not implement HTTP, routes, and resources as independent reply vocabularies that each pass their family fixtures while missing the shared substrate — that is the classic port trap this section exists to prevent.

**Read.** [`spec/Managed-Effects.md` §The uniform reply envelope](https://day8.github.io/re-frame2/spec/Managed-Effects/#the-uniform-reply-envelope) (the canonical normative home — the reply map, reply target, closed status taxonomy, work-id correlation, mandatory stale suppression, and the reply-mapping functor law) and [EP-0011](https://day8.github.io/re-frame2/EP/EP-0011-uniform-async-reply-envelope/).

**Contract — one reply map, one target, one closed status, across all async families.** Every managed effect whose completion crosses an event boundary reports it through **one** uniform envelope:

- **One reply target.** The canonical public target key is `:rf/reply-to` (short vector form, or the internal descriptor form). A family MAY expose its own public sugar — HTTP `:on-success` / `:on-failure`, machine `:on-done`, route-loader threading — but that sugar **lowers to `:rf/reply-to` internally**; it is not a parallel mechanism. (For HTTP, the public `:on-success` / `:on-failure` `{:kind …}` payload is **sugar reshaped from** the internal envelope — the canonical reply map is internal for HTTP. Do not expose `:status` / `:work/id` / `:completed-at` on the public HTTP payload.)
- **One closed status.** Completion produces a reply map carrying exactly one `:status` from the closed set `{:ok :partial :error :cancelled :stale}`. Timeout is **not** a top-level status (it is `:status :error` + `:work/status :timed-out`); stale wins over the natural completion status for delivery.
- **`:work/id` is the single attempt identity.** Ledger-backed work correlates by `:work/id` (the family owns the tuple head — `[:rf.work/http …]` / `[:rf.work/resource …]` / `[:rf.work/route …]` / `[:rf.work/machine …]`). Any other id (HTTP `:request-id`, route `:nav-token`) is `:correlation` metadata, never a second stale-suppression key (EP-0007: one attempt, one `:work/id`).
- **Stale suppression is the correctness boundary.** Each superseded-able family defines **data-only** suppression gates validated before any durable write. A stale reply MUST NOT run the app target, becomes `:status :stale`, reaches `:suppressed` in the ledger, and produces no user-visible app-db/runtime-db mutation. Cancellation is only an optimization.
- **`:completed-at` is causal.** Durable timestamps source from `(:completed-at reply)` / the causal token (EP-0010), never a fresh ambient clock read at the reducer — or epoch-restore / SSR / time-travel replays to a different value.
- **Reply-envelope facts are observable.** Emit trace rows from the reply-envelope facts (issuance, retries, cancellation-requested, the five-status completion, stale suppression, delivery-or-non-delivery), routing every wire-bearing slot through `rf/elide-wire-value` (property 5), so Xray / pair tools read the canonical reply substrate — not private callback facts.

**Acceptance.** The conformance corpus does not yet ship dedicated reply-envelope fixtures, so a port verifies Property 9 with its **own equivalent unit tests**, cross-family: one reply map + one target per family; lower family sugar to `:rf/reply-to`; the `:status` set is exactly the closed five; a superseded attempt suppresses (no app target, no durable write, a `:stale` ledger/trace row); `:completed-at` replays deterministically; and the reply-mapping functor law holds (`complete(map-completed-event(f, target), reply) == f(complete(target, reply))` — mapping a target changes only the completed event, not issuance / work id / status / cancellation / stale checks / tracing). If a port skips a family's async surface, it skips that family's slice of this obligation — but it must not implement an async family *without* it.

### The derivation/process algebra (EP-0014)

> **Cross-cutting view gated by the optional Tool-Pair inspection surface.** A sibling to the [shared path + identity foundation](#the-shared-path--identity-foundation-ep-0012) — a single shape every declared fact and process lowers to — but unlike that foundation it is **not** core: a port that implements subs/flows/resources/routes/machines already satisfies it, and the only EP-0014-specific build is the *optional* graph-inspection surface gated by D3 Q6 (the Tool-Pair section directly below). It sits here, next to Q6, for that reason.

**re-frame2 names one vocabulary every declared fact and process over the frame fold lowers to.** Subscriptions, runtime subscriptions, flows, resources, route facts, and machine selectors are five *plural source forms* — but for inspection, testing, and specification they are **one model**: a node with declared **inputs**, an **output** fact/address, a **storage class** (where the local representation lives), an **evaluation policy** (when it runs), and a **lifecycle/owner** (who keeps it alive). [`spec/Derivations.md`](https://day8.github.io/re-frame2/spec/Derivations/) is the named-shape family member for derivations/processes — the third sibling beside [`spec/Managed-Effects.md`](https://day8.github.io/re-frame2/spec/Managed-Effects/) (the shape every framework-owned *effect* satisfies) and [`spec/Runtime-Subsystems.md`](https://day8.github.io/re-frame2/spec/Runtime-Subsystems/) (the shape every framework-owned *durable-state subtree* satisfies). Like the path foundation, it is a **shared view, not a new authoring surface**.

**What a port must internalise (and what it does NOT have to build).**

- **No new authoring primitive, no public accessor name.** There is **no** `reg-fact` / `reg-derivation` and **no** stable public graph-accessor name in this slice — the *project-before-primitive* discipline (prove the projection from the existing `reg-sub` / `reg-flow` / `reg-resource` / `reg-route` / `reg-machine` forms before minting a primitive). A port that implements those five source forms to their owning EPs (006 / 013 / 016 / 012 / 005) **already conforms** to the algebra; there is nothing extra to expose publicly. Implementing the algebra view is gated by whether you build the **optional** tooling/inspection surface (Tool-Pair / the conformance graph fixtures), not by core.
- **Two closed superkinds; refinements ride a separate axis.** Every node's `:kind` is exactly one of `:derivation` (subscriptions, flows — a pure whole-value computation, ephemeral or materialized) or `:process` (resources, routes, machines — a derivation *with* state, lifecycle, and commands over time). The refined labels (`:resource-process`, `:route-fact`, `:machine-process`, `:machine-selector`) are **informative refinements carried on a separate `:refinement` axis, never in `:kind`** — so a tool that understands only the two superkinds classifies every node by `:kind` alone. A machine *selector* stays an ordinary `:derivation` subscription node (machines do **not** become a second subscription system).
- **Storage is always local; `:remote` is NOT a storage class.** The four storage classes are `:ephemeral` / `:app-db` / `:runtime-db` / `:host-transient` — each naming **where the local representation lives**. Remote authority is a **separate `:authority` axis** (`{:kind :remote :system :server :transport …}`), present only when the source of truth is external. A resource is `:storage :runtime-db` (the local cache entry) **plus** `:authority {:kind :remote …}` — never `:storage :remote`. A port wiring resource tooling must keep these two facts distinct, and the `:authority`'s `:transport` is a *projection* of the EP-0016 registration fact, not a second authoritative home.
- **The don't-execute rule.** Static graph inspection **never invokes a node's param/scope functions** — it reads declarations. A parametric input set (a query-dependent sub input fn, a resource's `:params`/`:scope` fn) is reported as the marker `:parametric`; only the *live* graph (observing realized cache entries) shows concrete edges. A `{:from-db <resolver-id>}` named scope resolver is the exception that stays *static* (its id + declared inputs are facts). A port's tooling that speculatively runs declarations to enumerate edges is non-conforming.
- **The whole-value law is the semantic floor.** A conforming implementation MUST be correct if every derivation recomputes its entire output from its declared inputs: `(= (derive inputs ctx) (read-output-after-recompute inputs ctx))`. Memoization, equality pruning, dirty-checks, and deltas are *implementation techniques* that MUST NOT change the observable value. Slice-1 ships **no executable delta protocol** — the optional delta law (deltas must *commute* with whole-value recomputation) is stated and deferred; a port with no delta path still conforms. This is the rule EP 006 and EP 013 cite for sub/flow correctness; your port already needs it.

**Reserved schema fields.** The node schema reserves three optional fields (`:realm/id` / `:app/id` / `:module/id`), **never required in slice-1** and **never populated** — they are a reserved-key carve-out the spec still keeps (see [`spec/Spec-Schemas.md` §`:rf/derivation-node`](https://day8.github.io/re-frame2/spec/Spec-Schemas/) and [`spec/Derivations.md`](https://day8.github.io/re-frame2/spec/Derivations/)). The algebra view is **registrar-derived** — assembled from registration metadata, full stop. A port does not populate these keys and does not build any value-relocation path; just don't repurpose them while the reservation stands.

**Conformance.** There is no dedicated `:derivation/*` family — the algebra is verified *through* the source-form fixtures that already exist (the `:core/*` sub fixtures, `:flow/*`, resources / routing / machines families) plus, **if the port builds the optional inspection surface**, the graph-inspection checks in [`spec/Derivations.md` §Conformance](https://day8.github.io/re-frame2/spec/Derivations/#conformance): source lowering (each source form exposes the expected id/kind/inputs/output/storage/evaluation/lifecycle), static-vs-live separation with the don't-execute rule, storage classification (no node uses `:remote` as storage), evaluation-policy invariants (on-demand reads cause no durable writes), lifecycle release on teardown, tool redaction without losing graph *structure*, and the whole-value/delta law. A port that ships no graph-inspection tooling puts these on `known-skipped-capabilities` with a "no inspection surface built" reason — the *behaviour* is still covered by the per-EP source-form fixtures.

Per [`spec/Derivations.md`](https://day8.github.io/re-frame2/spec/Derivations/); design rationale in [`docs/EP/EP-0014-derivation-and-process-algebra.md`](https://day8.github.io/re-frame2/EP/EP-0014-derivation-and-process-algebra/). The Malli shapes are projected into [`spec/Spec-Schemas.md` §`:rf/derivation-node`](https://day8.github.io/re-frame2/spec/Spec-Schemas/).

### Tool-Pair attachment surface (if D3 Q6 is yes)

> **Q6 = yes is mostly reproduction, plus three additions.** A `yes` to Q6 (Tool-Pair adapters) does NOT mean a big new subsystem. Per [`spec/Tool-Pair.md` §What re-frame2 commits to](https://day8.github.io/re-frame2/spec/Tool-Pair/#what-re-frame2-commits-to-the-runtime-contract), **every capability a pair-shaped tool needs except time-travel is already specified by the EPs you built** — registrar query (001/002), trace stream (009), hot-swap-via-re-registration (001), `:fx-overrides` stubbing (002/008), source coords (001/006), `compute-sub` headless reads (008), schema introspection (010 if Q4≠no), `flush-render!` (the optional 006 adapter fn). Q6 is the obligation to **expose those surfaces coherently for a REPL-attached agent**, plus the three genuinely-new pieces below. Do not re-build a parallel inspection API; the EP surfaces ARE the contract.

**Read.** [`spec/Tool-Pair.md`](https://day8.github.io/re-frame2/spec/Tool-Pair/) end-to-end (the consolidated runtime contract + §How AI tools attach), [Implementor-Checklist §TP1](https://day8.github.io/re-frame2/spec/Implementor-Checklist/#tp1-tool-pair-adapters) for the host-by-host attach mechanism, and the epoch-history / `restore-epoch!` / `replace-frame-state!` rows in [`spec/API.md`](https://day8.github.io/re-frame2/spec/API/).

**The three additions over the EP surfaces you already have.**

- **Time-travel — the one new surface.** Epoch recording, query, restore, and injection are NOT covered by EPs 001–015. Implement the `:rf/epoch-record` ring (bounded, default depth 50, `(rf/configure! {:epoch-history {:depth N}})`), `(rf/epoch-history frame-id)` (oldest-first), `(rf/restore-epoch! frame-id epoch-id)` (rewinds the **whole frame-state** — both partitions atomically via `replace-frame-state!`, NOT app-db alone, per EP-0001's two-partition contract; emits `:rf.epoch/restored`), `register-epoch-listener!`, and the state-injection trio `replace-app-db!` / `replace-runtime-db!` / `replace-frame-state!` (each records a synthetic epoch so restore can rewind past it). Restore is a no-op-on-failure query with a closed `:rf.epoch/*` failure taxonomy (`:rf.epoch/restore-during-drain` when called mid-drain, …). The CLJS reference's `epoch/` artefact is the worked example ([`reference-impl-tour.md` §`epoch/`](reference-impl-tour.md)). Per [`spec/Tool-Pair.md` §Time-travel](https://day8.github.io/re-frame2/spec/Tool-Pair/#time-travel-epoch-snapshots-and-undo).
- **Direct-read egress fails closed.** Direct-read tools (`app-db-value` / `snapshot-of` / the sub-cache read) bypass the trace surface where EP 015 classification stamps, so they MUST route their returned value through `project-egress` / `elide-wire-value` at the off-box boundary with sensitivity defaulting OFF (`:rf.egress/off-box-tool` redacts; `:rf.egress/local-raw` is the explicit trusted-local opt-in). This is the same EP 015 boundary primitive — do not let a tool read ship raw. Per [`spec/Tool-Pair.md` §Direct-read privacy](https://day8.github.io/re-frame2/spec/Tool-Pair/#direct-read-privacy-posture-for-sub-cache-and-get-path) and the epoch off-box-projection rule in [`spec/Security.md` §Privacy](https://day8.github.io/re-frame2/spec/Security/).
- **Tooling-security obligations apply.** A pair tool that ships source-map clickthrough hits the editor-URI scheme allowlist, and any pair log/recorder writer hits the file-path boundary — both spec-pinned MUSTs. See [§Tooling-security obligations](#tooling-security-obligations-any-port-that-ships-tooling) below.

**Conformance.** Q6 also gates the optional **derivation/process graph-inspection** surface (the split pair `:derivation/algebra-graph` / `:derivation/algebra-graph-subs-machines`) — see [§The derivation/process algebra (EP-0014)](#the-derivationprocess-algebra-ep-0014) and `conformance.md` §Capability tagging. The attachment surfaces themselves are verified through the EP families that own them (`:core/*`, etc.); a port shipping no inspection graph records that as a `known-skipped-capabilities` reason.

### EP 016 — Resources (if D3 Q10 = yes)

**Read.** [`spec/016-Resources.md`](https://day8.github.io/re-frame2/spec/016-Resources/) — the full identity rules, scope resolution, the lifecycle FSM, the work ledger, race / in-flight semantics, route integration, SSR/hydration, and the `:rf.resource/*` / `:rf.mutation/*` surfaces. Keep the resource-registrar rows in [`spec/API.md`](https://day8.github.io/re-frame2/spec/API/) open for the exact public signatures. **Do EP 014 first** — Resources lower onto managed HTTP, so Q10 presupposes Q9.

**Contract.** The three late-bound registrar kinds `:resource`, `:mutation`, `:resource-scope` and their public surface — `reg-resource` / `clear-resource`, `reg-mutation` / `clear-mutation`, `reg-resource-scope` / `clear-resource-scope`, plus the `resolve-resource-scope` resolver helper (`(resolve-resource-scope db scope-id)` — a **pure**, trace-free resolver over the registry: not an effect, no app-state / dispatch side effects, and **no** `:rf.resource/scope-resolved` trace, because a passive scope read advertised as pure must not mutate observability state; `:rf.resource/scope-resolved` is emitted only at the **causal** resolution boundaries — a resource event's `{:from-db …}` scope, route entry, mutation settle, and the clear-scope diagnostics — never by the helper or by subscription key resolution, which would flood the trace bus). The keyword-addressed events (`:rf.resource/ensure` / `:rf.resource/refetch` / `:rf.resource/release-owner` / `:rf.resource/invalidate-tags` / `:rf.resource/clear-scope`, `:rf.mutation/execute`), the passive `:rf.resource/*` / `:rf.mutation/*` subscriptions, and `:rf.runtime/resources` reserved **runtime-db** storage (NOT app-db — EP-0001's two-partition contract; the cache is never hand-edited via a `:db` effect). The **scoped resource key** `[canonical-scope resource-id canonical-params]` is built on the one shared CEDN-1 canonical-identity rule (see [§The shared path + identity foundation](#the-shared-path--identity-foundation-ep-0012)) — scope is **required** at registration and **fail-closed** (an unresolvable scope is a loud error, never a silent shared read). The EP-0016 completion surface: named `reg-resource-scope` resolvers referenced as `{:from-db <id>}`, per-target **scoped invalidation descriptors** (`[{:scope … :tags …}]`, with `:rf.scope/same` / `:rf.scope/global` / a concrete scope / a resolver reference, and `:cross-scope?` as the audited broad opt-out), **populate-as-authoritative-load**, map-form exact targets, and call-site **`:reply-to`** mutation-completion continuations (the workflow axis, kept separate from the declarative cache axis).

**Request decoration reuses the managed-HTTP seam.** Auth/tracing/base-URL/retry for resource reads and mutations is the existing `reg-http-interceptor` / `clear-http-interceptor` (EP 014), registered once per frame and applied to every `:rf.http/managed` request — NOT a new resources surface. Retry defaults stay read-focused (a mutation arms retry only when its own `:request` declares it).

**Conformance.** Claims the `:rf.resource/*` / `:rf.mutation/*` family. **Corpus-behind caveat:** Resources is post-v1 / drafting, and the corpus ships **no** resource fixtures yet (`grep -rho ':rf.resource/' spec/conformance/fixtures/` returns nothing at corpus HEAD) — the same fixture-less-but-spec-mandated shape as `:actor/own-state`. So a Q10=yes port verifies the surface against `spec/016-Resources.md` + its own unit tests today, and adds the conformance claim once fixtures land; don't read the absent tags as "Resources isn't a real conformance family." A Q10=yes port that implements only part of the surface puts the unimplemented capability tags on `known-skipped-capabilities`.

### Composition substrate: image → frame → event stream (EP-0023)

> **The composition model is `image → frame → event stream`** ([EP-0023](https://day8.github.io/re-frame2/EP/EP-0023-image-loaded-frames/)). A feature namespace registers ordinary `reg-*` forms; an **`rf/image`** selects a registration set by `:select-ns` provenance; an **`rf/make-frame`** builds a frame and runs it against a resolved image generation; the frame processes an ordered **event stream**. There is **no realm / app / install / module composition vocabulary** to build — the public model is image + frame, and registration resolution is frame-derived. Build one registrar, the boot-bound adapter selection, and the capability map; nothing wraps them in a realm/container layer.

> **No multi-realm / app-value substrate — do not build it.** Frame isolation + the resolved image generation are the whole isolation and composition story. A port does **NOT** build or conformance-check: any realm construction / routing / query / lifecycle, `install!` / `reinstall!` seating, `realm-ids` / `frame-realm` reads, inert `module` / `app` composition values, per-container registrar atoms, or multi-adapter-by-N-realms. None of that vocabulary exists in the model.

**Read.** [EP-0023](https://day8.github.io/re-frame2/EP/EP-0023-image-loaded-frames/) (the `image → frame → event stream` public model), the `rf/image` / `make-frame` / `frame-value->id` / `reload-images!` and frame-targeted registrar-query rows in [`spec/API.md` §Registration](https://day8.github.io/re-frame2/spec/API/#registration), and [`spec/002-Frames.md`](https://day8.github.io/re-frame2/spec/002-Frames/) (a frame is addressed by its process-local frame id; resolution is frame-derived). A port MAY expose `rf/migration-map` / `rf/migration-explain` to surface, as inspectable data, which names are not part of the API.

**Contract.** The public composition surface a port exposes:

- **`rf/image`** — the public value for a selected registration set. A feature namespace registers ordinary `reg-*` forms; an image selects them by `:select-ns` provenance (namespace-provenance selection **fails loud** rather than silently assembling an incomplete image). The image carries the selected registrations, metadata, provenance, ownership claims, and framework standard registrations.
- **`rf/make-frame`** — the ONE frame constructor. Builds a live frame and returns the **frame value** (a lifecycle token; `dispatch` / `subscribe` / `destroy-frame!` accept the value OR its id). `:images` present and non-empty ⇒ the selected image generation (a vector; `[]` is an error — `:rf.error/make-frame-bad-images`, EP-0026), absent ⇒ the **default image generation** over the whole source store plus framework standards (failing loud on a cross-namespace same-`[kind id]` collision). Read a frame value's id with **`frame-value->id`**. The public routing address is the **process-local frame id** — no realm coordinate.
- **`rf/reload-images!`** — hot-reloads a frame's image generation in place, preserving frame memory (durable state survives). `:frame` is a registered frame id or a frame value.
- **Frame-derived resolution.** Every registration lookup a frame performs resolves through that frame's resolved image generation. The public registrar-query map arity is ALWAYS frame-targeted — `(registrations {:frame f :kind k})` resolves through frame `f`'s sealed image generation; a map without `:frame` is an error (`:rf.error/registrar-query-needs-frame`).

Behind this, the framework holds the one registrar, the boot-bound adapter selection, and the capability map directly — there is no realm/container layer wrapping them, nothing extra to build, document, or conformance-check.

**Conformance / acceptance.** Verify against the `image → frame → event stream` model: an `rf/image` selects only the `:select-ns`-provenance registrations (and fails loud on a missing-provenance selection rather than assembling an incomplete image); `make-frame` with `:images` runs the frame against that image's generation, and two frames on one page can reuse the same readable registration ids without global clobbering (frame isolation); `reload-images!` swaps a frame's generation while preserving its durable state; frame-targeted registrar queries resolve through the live frame's generation, and a map without `:frame` errors. Do **NOT** author any realm/app/module acceptance checks (inert module/app values, `install!` capability-gate diffs, `reinstall!` add/change/remove deltas, per-realm registrars, `realm-ids` / `frame-realm` reads, multi-container conformance) — that machinery is not part of the model.

## Tooling-security obligations (any port that ships tooling)

> **Spec-pinned, not optional, and not gated by a D3 question.** [`spec/Implementor-Checklist.md` §Security obligations for implementation tooling](https://day8.github.io/re-frame2/spec/Implementor-Checklist/#security-obligations-for-implementation-tooling) names two MUSTs that bind **any port shipping tooling** — and "tooling" includes the conformance harness itself (which every conformant port ships) plus test-fixture emit, scaffolding scripts, story/recorder dumps, and the Q6 pair surface. [`spec/Security.md`](https://day8.github.io/re-frame2/spec/Security/) is the pattern-level contract other-language ports read as binding (per its preamble: "Other-language ports … read this doc as contract"); the CLJS-reference bindings (named functions, numeric defaults) live in `implementation/SECURITY.md`. Wire these when the tooling surface first exists, not at v1-ship.

- **File-path boundaries for writing tools.** Every tool that writes to the filesystem AND accepts an env-var path override (fixture/corpus emit into a scratch dir, scaffolding output root, a recorder log writer) MUST resolve the override path — collapsing `..` and following symlinks — and check it against a **closed allowed-prefix list** of repo-rooted prefixes **before any write**. The CLJS reference allows exactly `implementation/` + `examples/`; your port picks the equivalent repo-rooted prefixes. An escape (a `..` that exits the roots, an absolute path outside them, a symlink resolving out) **fails fast** with a clear error naming the resolved path and the allowed list — no fall-through to a default location, no strip-and-pass, no silent `$HOME` write. The override is a CI-internal knob (regenerate fixtures into a per-build scratch dir), not a stable public API. Per [`spec/Security.md` §File-path boundaries](https://day8.github.io/re-frame2/spec/Security/#file-path-boundaries) and [`spec/Implementor-Checklist.md` §File-path boundaries for writing tools](https://day8.github.io/re-frame2/spec/Implementor-Checklist/#file-path-boundaries-for-writing-tools).
- **Editor URI scheme allowlist for source-map clickthrough (Q6 / any source-mapped tool).** A port that ships source-map clickthrough (or accepts custom editor templates like `{:custom "vim://%s:%d"}`) MUST **reject** URIs whose scheme is `javascript:`, `data:`, or `vbscript:` (case-insensitive) — the three known-bad schemes. Everything else passes with no dev burden (`vim:`, `idea:`, `subl:`, `org:`, `vscode:`, `cursor:`, future editor schemes). It is a **scheme-rejection denylist, not an allowlist** — don't enumerate good schemes. The check fires at **both** editor-template registration time and click-resolution time, so a template that interpolates user input into the scheme position is caught at the click too. Per [`spec/Tool-Pair.md` §Editor URI scheme allowlist](https://day8.github.io/re-frame2/spec/Tool-Pair/#editor-uri-scheme-allowlist) (canonical) and [`spec/Security.md` §Editor URI scheme allowlist](https://day8.github.io/re-frame2/spec/Security/#editor-uri-scheme-allowlist).

A port that ships an MCP/pair attach surface (Q6) inherits the broader MCP authority posture too — localhost-bind by default, the named-mutation-vs-eval gate split, and wire payloads through `elide-wire-value` — but those are tool-side calls, not framework primitives; [`spec/Security.md` §MCP tool authority and isolation](https://day8.github.io/re-frame2/spec/Security/#mcp-tool-authority-and-isolation) is the reference if your port also ships the tool half.
