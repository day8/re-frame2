# silent-runtime-failures — the checklist of what compiles clean and breaks at runtime

A real re-frame v1 → re-frame2 migration **compiled with zero errors** and still had **five-plus distinct runtime breaks, several completely silent**: the app booted to a spinner that never cleared, a sub returned `nil` forever, a machine died a beat after it started. None of these showed in the build log. All of them required reading **live `app-db` + machine snapshots** to find.

That is the structural shift this leaf exists to name: **v2 moves a large class of v1 failures from compile-time to runtime.** v1 leaned on dynamic Vars and an ambient global `app-db` atom, so many shape mistakes surfaced as load-time or first-call exceptions. v2 is stricter at registration *and* relocates framework runtime into a separate **runtime-db** partition (`:rf.db/runtime`, children under `:rf.runtime/*`) — which means several legitimate-looking, cleanly-compiling rewrites fail **silently at boot** or throw at first dispatch. A green compile means *"the rewrites parse"*, not *"the app boots and runs."* **Treat the compile as the start of verification, not the end of it.**

This leaf is the **reference half** of Phase 4 — Verify (SKILL.md): it enumerates the known silent-runtime-failure modes and says why a compile cannot see them. The **procedure half** — the boot smoke-test loop you run to catch them, and the done-bar gates past the local dev build — is the sibling leaf [`runtime-smoke-test.md`](runtime-smoke-test.md).

## The silent-runtime-failure checklist

Each of these compiles clean and breaks at runtime. Walk the list against the just-migrated app — every row names the symptom, the cite, and the live read that confirms it. (Several of these are the same Type-B rules the sweep already flagged; the point here is that **applying the rewrite is not the same as verifying it boots** — the runtime read is the verification step.)

| # | Silent failure | Compiles? | Symptom at runtime | Rule / cite | Live read that confirms |
|---|---|---|---|---|---|
| 1 | **`reg-sub` signal-function form** (the v1 3-arity `(reg-sub id signal-fn computation-fn)`) | yes — and it **registers** fine too (two trailing fns parse as a valid `:parametric` sub); the live-reaction return is rejected later, at **first subscribe / materialization**, not at registration or compile | the sub never produces a value; views deref `nil`; the first materialization throws `:rf.error/sub-input-fn-bad-return` and recovers to a `nil`-yielding reaction (never silently no-inputs) | **M-71** ([`guided-interceptors-subs.md` §M-71](guided-interceptors-subs.md#m-71--the-v1-signal-function-reg-sub-form-3-arity--v2-input-fns)) — the v1 signal fn → v2 `input-fn` rewrite; **Type B** | `read-sub {sub: "[:the/sub …]"}` returns `nil` or errors; scan the trace (after the first deref, not at ns-load) for `:rf.error/sub-input-fn-bad-return` |
| 2 | **Per-feature artefact missing** — code calls a machines / routing / schemas / http / ssr surface but the artefact dep + its `:require` are absent | yes (the call site resolves through the `re-frame.core` re-export) | first dispatch to the surface throws `:rf.error/<artefact>-missing` (e.g. `:rf.error/http-artefact-missing`, machine events silent-no-op) | **M-28 / M-29 / M-30 / M-31 / M-32** ([`breaking-changes.md`](breaking-changes.md#required-m-rules-by-trigger-surface)) — the artefact-add rules; M-31's `re-frame.http` vs `re-frame.http.managed` two-require trap is the classic | dispatch the feature event, then `read-sub` / `get-path` the slot it should write — nothing landed; the trace carries the `*-missing` error |
| 3 | **A handler returns a `:db` carrying the retired `:rf/runtime` app-db root** — a v1-shaped `:initialize-db` / `:bootstrap` / reset handler whose `fresh-db` still stashes a `:rf/runtime` key, or an older preview rewrite that explicitly `assoc`'d it back | yes | *loud-at-runtime, NOT loud-at-compile*: the post-commit guard throws `:rf.error/legacy-runtime-root` on the event. (The old silent-clobber footgun is **structurally gone** — runtime-db is a separate partition a `:db` return cannot touch, so a wholesale `{:db fresh-map}` replace that carries **no** `:rf/runtime` is safe and leaves machines/routing untouched.) | **M-15b** ([`guided-handlers-state.md` §M-15b](guided-handlers-state.md#m-15b--wholesale-app-db-replace--the-retired-rfruntime-root)) — the retired `:rf/runtime` root is a hard error (always-on, [Conventions §The legacy `:rf/runtime` root](https://github.com/day8/re-frame2/blob/main/spec/Conventions.md#the-legacy-rfruntime-root-hard-error-in-final-form)) | scan the boot trace for `:rf.error/legacy-runtime-root`; confirm boot machines have a live snapshot via the canonical `read-sub {sub: "[:rf/machine <id>]"}` — the snapshot lives in runtime-db, so `get-path` (a `get-in` against **app-db**) cannot reach `[:rf.runtime/machines :snapshots]` |
| 4 | **An unfolded top-level `:dispatch` / `:dispatch-n` / custom-fx key** — the fold-into-`:fx` rewrite missed an effect-map key — *loud-at-runtime, NOT loud-at-compile* | yes — the map is valid Clojure, so the compile is clean | the effect-map top level is a **closed set of seven keys** (`:db`, `:rf.db/runtime`, `:fx`, `:sensitive`, `:large`, `:clear-sensitive`, `:clear-large`); a foreign key **refuses the whole event pre-commit** — nothing commits, not even the handler's `:db` write — and `:rf.error/effect-map-shape` (recovery `:fix-effect`) rides the **always-on** channel, so it survives a production build | **M-8** ([`breaking-changes.md`](breaking-changes.md#required-m-rules-by-trigger-surface)); the corpus call-out is **M-8** in [`MIGRATION.md`](https://github.com/day8/re-frame2/blob/main/migration/from-re-frame-v1/README.md) | dispatch the event and watch for `:rf.error/effect-map-shape` naming the offending key; the slot the handler's `:db` write should have produced is **also** unchanged, because the event aborted whole |
| 5 | **A `(when …)` nil-thread loses init state** — a handler guards its `:db` return with a `(when cond …)` that returns `nil` on the false branch; v2 commits the `nil` (or treats "no `:db` key" as "no change"), silently dropping the seed | yes | initial session / seed state is missing; downstream subs read `nil`; intermittent (only on the false branch) | general handler hazard — flag under **M-15** db-seeding review ([`guided-handlers-state.md` §M-15](guided-handlers-state.md#m-15--top-level-app-db-seeding)) | `get-path` the seeded slot right after boot — it's `nil`; reproduce by hitting the branch that returns `(when …)` |
| 6 | **An event interceptor chain outside metadata `:interceptors`** — bare `(rf/reg-event-db :id mw/x handler)`, positional vector `(rf/reg-event-db :id [mw/x] handler)`, or metadata-plus-vector `(rf/reg-event-db :id {:doc "..."} [mw/x] handler)` — *loud-at-runtime, NOT loud-at-compile* | yes — the **compile passes clean**; the throw is at ns-load / first page-load, so march-the-wall never sees it | `reg-event-*` throws `:rf.error/reg-event-bare-interceptor`, `:rf.error/reg-event-bad-middle-slot`, or `:rf.error/reg-event-bad-arity` at ns-load, which **aborts the rest of that ns** — a boot machine's `reg-machine` after it never registers; the app **hangs at boot** (spinner never clears) | **M-70** ([`breaking-changes.md`](breaking-changes.md#required-m-rules-by-trigger-surface), [`auto-cross-cutting.md` §M-70](auto-cross-cutting.md#event-interceptor-chains--metadata-interceptors-m-70--mechanical-loud-at-runtime-not-loud-at-compile)) — Type A, structural up-front grep | **the boot console** — the registration throw lands there the instant the app loads (no app-db read needed); scan the boot trace for it. This is the loud-but-only-at-runtime member of the list — the structural grep finds it before boot |
| 7 | **A retired event registrar still called at registration** — any surviving `(rf/reg-event-db …)` / `(rf/reg-event-fx …)` / `(rf/reg-event-ctx …)` not yet migrated to `reg-event` (EP-0018 collapsed all three) — *loud-at-runtime, NOT loud-at-compile* | yes — the var resolves, so the **compile passes clean**; the throw fires at ns-load / registration | `reg-event-*` throws its always-on hard error `:rf.error/reg-event-db-removed` / `:rf.error/reg-event-fx-removed` / `:rf.error/reg-event-ctx-removed` at registration — the call is rejected (`:no-recovery`, the handler is **not** registered) and the throw **aborts the rest of that ns's load** (everything after it, incl. a boot machine's `reg-machine`, never registers → the app **hangs at boot**) | **M-73** ([`breaking-changes.md`](breaking-changes.md#required-m-rules-by-trigger-surface), [`auto-call-site-rewrites.md` §M-73](auto-call-site-rewrites.md#m-73--one-event-registration-form-reg-event)) — the one-event-form collapse; a static pre-boot grep `reg-event-(db\|fx\|ctx)` finds every site without a runtime | **the boot console** — the `:rf.error/*-removed` throw lands there the instant the app loads (no app-db read needed); also caught by the static grep up front |
| 8 | **A `reg-sub` `:->` / `:=>` flat-sub sugar registration still in the source** — v1.3+ sugar (`(reg-sub :id :-> f)` / `:=>`) that v2's `reg-sub` parser does not accept (only `:<-` chains, the two-fn parametric form, and a single trailing fn) — *loud-at-runtime, NOT loud-at-compile* | yes — `:->` / `:=>` are just keywords, so the form **parses + compiles clean**; the throw is at registration / ns-load | `reg-sub` throws `:rf.error/reg-sub-bad-args` (`:recovery :no-recovery`) at registration — the sub is **not** registered and the throw **aborts the rest of that ns's load** (later `reg-event` / `reg-machine` / top-level `make-frame` never run → a boot that depends on them hangs) | reg-sub `:->` / `:=>` removal (no `M-N`): [`auto-call-site-rewrites.md` §reg-sub flat-sub sugar removed](auto-call-site-rewrites.md#reg-sub-flat-sub-sugar-removed), [`breaking-changes.md` §What stays the same](breaking-changes.md#what-stays-the-same-do-not-change) — a static pre-boot grep `reg-sub` … `:->` / `:=>` finds every site | **the boot console** — the `:rf.error/reg-sub-bad-args` throw lands there at first ns-load (no app-db read needed); also caught by the static grep up front |
| 9 | **A bare `dispatch` / `subscribe` in an async callback outside any view + outside an explicit frame scope** — a module-level `addEventListener` (popstate / hashchange), a `setTimeout` / `setInterval` / `requestAnimationFrame` timer, a `js/window` `'error'` / `onerror` handler, or a third-party JS-lib lifecycle callback — *loud-at-runtime, NOT loud-at-compile, and the boot scan can MISS it* | yes — compiles clean; **and a "does it boot without throwing?" scan can pass**, because the listener / timer / error handler fires only when its event arrives, which may be after the scan | the callback throws `:rf.error/no-frame-context` at **first FIRE** (EP-0002 — no ambient `:rf/default`; a registration-time `with-frame` does **not** survive into the async callback). The fix re-establishes the frame INSIDE the callback (`with-frame` at fire time, or a closed-over `(rf/capture-frame)`) | **M-11** (async / non-render class — [`guided-views-m11.md` §The async listener timer and error-handler class](guided-views-m11.md#the-async-listener-timer-and-error-handler-class)); complements the view (M-11) + boot-kick (M-40) instances | **exercise the listener / timer / error paths**, not just boot — trigger a route change / let a timer elapse / raise an error, then watch the console for `:rf.error/no-frame-context`. A boot-without-firing scan won't surface it |

The list is **open** — confirmed modes from one field report, not an exhaustive set. Each row states its own loud-or-silent classification; what they share is that **none is loud at compile**, which is why they belong here. Two caveats the columns cannot carry: rows 6, 7 and 8 are also found by a **static pre-boot grep**, so they don't need a runtime to be caught — but a missed survivor only ever shows at boot; and **row 9 fires only when its async callback is triggered**, so even a clean boot smoke-test can pass while it lurks — the inventory grep for listener / timer / error sites *plus exercising those paths* is what catches it. The discipline generalises: **after any non-trivial rewrite, read the live app-db slot the rewrite was supposed to affect, and watch the boot console for `:rf.error/*` throws.** A green compile cannot tell you whether the value actually landed — nor whether an ns aborted its load.

## Why a compile can't catch these

| v1 mechanism | v2 mechanism | Consequence for the migrator |
|---|---|---|
| `reg-sub` accepted a signal-fn (live-reaction return) at any arity | `reg-sub` accepts the two-fn shape as a valid `:parametric` registration; the live-reaction return is rejected at **first materialization** with `:rf.error/sub-input-fn-bad-return` (recover-to-nil) | parses **and registers** fine; dies on first `subscribe` — a *runtime* event, not a compile or registration error (#1) |
| add-on surfaces were single-jar | per-feature artefacts; `re-frame.core` re-exports resolve even when the artefact is absent | the call site compiles; the **fx isn't registered**; first dispatch throws (#2) |
| framework runtime lived outside `app-db` | framework runtime lives in a **separate runtime-db partition** (`:rf.db/runtime`); a `:db` return cannot touch it, and a `:rf/runtime` app-db root is a hard error | a wholesale `{:db fresh}` replace is now safe; a `:db` carrying a retired `:rf/runtime` key throws `:rf.error/legacy-runtime-root` (#3) |
| effect maps accepted top-level `:dispatch` etc. | the effect-map top level is a **closed set of seven keys**; a foreign key refuses the whole event pre-commit, always-on | a missed M-8 fold compiles clean, then **aborts its event** on first execution — siblings and all (#4) |

The common thread: v2's stricter contracts and its two-partition runtime model (app-db + a framework-owned runtime-db) are *correct* design choices (they buy atomic revertibility, SSR survival, and tooling visibility — and make the old wholesale-replace clobber structurally impossible), but they relocate the remaining failures from "won't compile" to "compiles, boots wrong." The live-introspection smoke-test is the cheap insurance.
