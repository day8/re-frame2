# runtime-smoke-test — "compiles" is NOT the done-bar

A real rf8 → re-frame2 migration **compiled with zero errors** and still had **five-plus distinct runtime breaks, several completely silent**: the app booted to a spinner that never cleared, a sub returned `nil` forever, a machine died a beat after it started. None of these showed in the build log. All of them required reading **live `app-db` + machine snapshots** to find.

That is the structural shift this leaf exists to name: **v2 moves a large class of v1 failures from compile-time to runtime.** v1 leaned on dynamic Vars and an ambient global `app-db` atom, so many shape mistakes surfaced as load-time or first-call exceptions. v2 is stricter at registration *and* relocates framework runtime into a separate **runtime-db** partition (`:rf.db/runtime`, children under `:rf.runtime/*`) — which means several legitimate-looking, cleanly-compiling rewrites fail **silently at boot** or throw at first dispatch. A green compile means *"the rewrites parse"*, not *"the app boots and runs."* **Treat the compile as the start of verification, not the end of it.**

This leaf is the detail behind **Phase 4 — Verify** (SKILL.md). It does two things: enumerates the known **silent-runtime-failure modes** as a checklist, and prescribes a **boot smoke-test with live introspection** to catch them.

**"Compiles clean" is not even a registration check — the retired event registrars prove it, and they make the runtime boot-smoke MANDATORY.** EP-0018 collapses `reg-event-db` / `reg-event-fx` / `reg-event-ctx` into the one `reg-event`, and the three retired names survive only as **facade-exported `^:no-doc` throwing stubs**: the var still *resolves*, so the compiler stays silent (no undeclared-var), and each throws its always-on hard error — `:rf.error/reg-event-db-removed` / `:rf.error/reg-event-fx-removed` / `:rf.error/reg-event-ctx-removed` — the instant it is **called at registration (boot)**. A v1 app calls these at the top of nearly every event namespace, so it can compile 0-error / 0-warning and then throw in many namespaces at first load. This is the runtime complement of the compile-CAUGHT deleted-var register in [`breaking-changes.md`](breaking-changes.md) (those don't resolve, so the compiler names them): a throwing-stub var resolves and survives the compile by construction. So "compiles clean" is **not** sufficient verification — a runtime **boot-smoke** (load the app, scan the console for `:rf.error/*-removed` registration throws) is **mandatory**, and it is added to the checklist below (row 7) and the smoke-test loop (step 1).

## The silent-runtime-failure checklist

Each of these compiles clean and breaks at runtime. Walk the list against the just-migrated app — every row names the symptom, the cite, and the live read that confirms it. (Several of these are the same Type-B rules the sweep already flagged; the point here is that **applying the rewrite is not the same as verifying it boots** — the runtime read is the verification step.)

This is the loud-but-only-at-runtime member of the list — the structural grep finds it before boot |
| 7 | **A retired event registrar still called at registration** — any surviving `(rf/reg-event-db …)` / `(rf/reg-event-fx …)` / `(rf/reg-event-ctx …)` not yet migrated to `reg-event` (EP-0018 collapsed all three) — *loud-at-runtime, NOT loud-at-compile* | yes — the retired names are **facade-exported `^:no-doc` throwing stubs**, so the var resolves and the **compile passes clean**; the throw fires at ns-load / registration | `reg-event-*` throws its always-on hard error `:rf.error/reg-event-db-removed` / `:rf.error/reg-event-fx-removed` / `:rf.error/reg-event-ctx-removed` at registration — the call is rejected (`:no-recovery`, the handler is **not** registered) and the throw **aborts the rest of that ns's load** (everything after it, incl. a boot machine's `reg-machine`, never registers → the app **hangs at boot**) | **M-73** ([`breaking-changes.md`](breaking-changes.md#required-m-rules-by-trigger-surface), [`auto-call-site-rewrites.md` §M-73](auto-call-site-rewrites.md#m-73--one-event-registration-form-reg-event)) — the one-event-form collapse; a static pre-boot grep `reg-event-(db\|fx\|ctx)` finds every site without a runtime | **the boot console** — the `:rf.error/*-removed` throw lands there the instant the app loads (no app-db read needed); also caught by the static grep up front. This is the widest-blast-radius compile-silent member — a v1 app calls these in nearly every event ns |
| 8 | **A `reg-sub` `:->` / `:=>` flat-sub sugar registration still in the source** — v1.3+ sugar (`(reg-sub :id :-> f)` / `:=>`) that v2's `reg-sub` parser does not accept (only `:<-` chains, the two-fn parametric form, and a single trailing fn) — *loud-at-runtime, NOT loud-at-compile* | yes — `:->` / `:=>` are just keywords, so the form **parses + compiles clean**; the throw is at registration / ns-load | `reg-sub` throws `:rf.error/reg-sub-bad-args` (`:recovery :fix-registration`) at registration — the sub is **not** registered and the throw **aborts the rest of that ns's load** (later `reg-event` / `reg-frame` / `reg-machine` never register → a boot that depends on them hangs) | reg-sub `:->` / `:=>` removal (no `M-N`): [`auto-call-site-rewrites.md` §reg-sub flat-sub sugar removed](auto-call-site-rewrites.md#reg-sub-flat-sub-sugar-removed), [`breaking-changes.md` §What stays the same](breaking-changes.md#what-stays-the-same-do-not-change) — a static pre-boot grep `reg-sub` … `:->` / `:=>` finds every site | **the boot console** — the `:rf.error/reg-sub-bad-args` throw lands there at first ns-load (no app-db read needed); also caught by the static grep up front |

The list is **open** — confirmed modes from one field report, not an exhaustive set. (Rows 1, 2, 4, 5 are *silent* at runtime; rows 3, 6, 7 and 8 are *loud* at runtime — they throw on the console — but **not loud at compile**, which is why they belong here: the compile gate misses them just the same. Rows 6, 7 and 8 are also found by a **static pre-boot grep**, so they don't need a runtime to be caught — but a missed survivor only ever shows at boot.) The discipline generalises: **after any non-trivial rewrite, read the live app-db slot the rewrite was supposed to affect, and watch the boot console for `:rf.error/*` throws.** A green compile cannot tell you whether the value actually landed — nor whether an ns aborted its load.

## The boot smoke-test phase — live introspection, not just "it loads"

A migrated app needs a **runtime smoke-test** as a distinct verification step, separate from "the compile passed" and "the unit tests pass." The unit suite re-baselines counts (M-12) and exercises handlers in isolation; it does **not** prove the *assembled, booted* app wires up. The boot smoke-test does.

The cheapest tool that can see these failures is **live `app-db` + machine-snapshot inspection** — because every failure in the checklist above is invisible in the build log and shows only in the running runtime's state. Two equivalent surfaces:

- **The `re-frame2-pair` MCP** (the Tool-Pair contract) — attach to the running shadow-cljs build's nREPL and read the live frame. `orient` for the app shape, then drill: `read-sub {sub: "[:some/sub]"}`, `get-path {path: "[:rf.runtime/machines :snapshots]"}`, `snapshot {path: "[:rf.db/runtime]"}` (the runtime-db partition). This is the recommended surface for a migration check — it speaks the exact slices the checklist needs and refuses ambiguous-frame reads. (Switch to the **`re-frame2-pair` skill** for a live session — see the post-migration hand-off in SKILL.md.)
- **A bare shadow-cljs nREPL** if Tool-Pair isn't wired — eval `(re-frame.core/app-db-value :rf/default)` for the app-db partition, `(re-frame.core/runtime-db-value :rf/default)` for the runtime-db partition (machine snapshots at `[:rf.runtime/machines :snapshots]`). Same reads, less ergonomics.

**The "does it boot without throwing?" half needs no pair-MCP setup.** Steps 1 and 6 below — boot the app and scan the console for `:rf.error/*` throws (the retired-registrar `*-removed` stubs, the bare-interceptor `reg-event-*` shapes, `:rf.error/legacy-runtime-root`) — are a **plain browser-console** job: load the dev build, watch the console, and reload with an injected `window` `'error'` listener to capture the throwing stacks. Any CDP / devtools tool (or manual devtools) does it; **none of the `re-frame2-pair` MCP setup is required** — no global server install, no fresh session to register it, no preload. The pair MCP is *optional richer tooling*: it earns its setup for the live `app-db` slice reads in steps 2–5 (the silent-failure modes) and deeper interactive debugging, not for the boot-without-throwing gate. ([`re-frame2-pair` SKILL.md §Setup](../../re-frame2-pair/SKILL.md).)

> **Delegated / orchestrated / CI execution.** The loop below is the *interactive* default — the skill prints the reads and a human runs them. Under delegated / orchestrated / CI execution there is no human in the loop to paste, so a *sandboxed autonomous worker* (an isolated git worktree) or a *CI runner* boots the dev build and runs the introspection reads **itself, inside its own sandbox**, then posts the boot-smoke verdict (snapshots, seed slots, sub values, trace scan) into the PR body for *asynchronous* human ratification rather than blocking inline on a paste. The trust boundary — *arbitrary-code execution* — is unchanged; the sandbox stands in for the human's machine. See [`SKILL.md` cardinal rule 5 — the sandboxed-executor exception](../SKILL.md).

**The smoke-test loop (the author runs it — Cardinal rule 5; the skill prints the reads):**

1. **Boot the app** in a dev build with `interop/debug-enabled?` true (so the loud diagnostics — `:rf.error/*-missing`, `:rf.error/sub-input-fn-bad-return` — actually fire and reach the trace). Note the M-70 registration-shape errors (`:rf.error/reg-event-bare-interceptor`, `:rf.error/reg-event-bad-middle-slot`, `:rf.error/reg-event-bad-arity`, #6), the M-73 retired-registrar errors (`:rf.error/reg-event-db-removed`, `:rf.error/reg-event-fx-removed`, `:rf.error/reg-event-ctx-removed`, #7), the reg-sub flat-sub-sugar error `:rf.error/reg-sub-bad-args` (#8), and `:rf.error/legacy-runtime-root` (M-15b, #3) throw unconditionally regardless of the debug flag — they surface on the console at first boot either way.
2. **Read `[:rf.runtime/machines :snapshots]`** (in runtime-db) — every boot/singleton machine the app started should have a live snapshot here. **Empty-where-you-expected-one** means the machine never started (an `init!`/ordering problem, not a clobber — a `:db` replace cannot wipe runtime-db). And for each snapshot that IS present, assert the machine has **left its `:initial` state** — a converted machine still sitting in `:initial` after boot is a **silently-stalled await**: its awaited event is being produced in the un-addressed plain-global form, so it never arrives (the #1 machine-conversion silent failure; see [`async-flow-to-machines.md`](async-flow-to-machines.md)). If a boot event throws `:rf.error/legacy-runtime-root` it returned a `:rf/runtime`-bearing `:db` (checklist #3).
3. **Read the seed slots** the init handlers were supposed to write (`get-path` each one). **`nil`-where-you-seeded is #4 or #5** (dropped top-level key / nil-thread).
4. **Deref the subs** the first screen depends on (`read-sub`). **`nil`-or-error is #1 or #2** (signal-fn `reg-sub` / artefact-missing).
5. **Dispatch one real event per feature surface** (a machine event, a managed-HTTP request, a route change) and re-read the affected slot. **No-op-with-no-error is the artefact-missing or clobber tell.**
6. **Scan the dev trace** for any `:rf.error/*` / `:rf.warning/*` emitted during boot — these are the loud half of the failure surface and name the exact subsystem.

A migration is **not done when it compiles**. It is done when this loop comes back clean: every expected snapshot present, every seeded slot populated, every first-screen sub producing a value, and a clean boot trace.

## Why a compile can't catch these

| v1 mechanism | v2 mechanism | Consequence for the migrator |
|---|---|---|
| `reg-sub` accepted a signal-fn (live-reaction return) at any arity | `reg-sub` accepts the two-fn shape as a valid `:parametric` registration; the live-reaction return is rejected at **first materialization** with `:rf.error/sub-input-fn-bad-return` (recover-to-nil) | parses **and registers** fine; dies on first `subscribe` — a *runtime* event, not a compile or registration error (#1) |
| add-on surfaces were single-jar | per-feature artefacts; `re-frame.core` re-exports resolve even when the artefact is absent | the call site compiles; the **fx isn't registered**; first dispatch throws (#2) |
| framework runtime lived outside `app-db` | framework runtime lives in a **separate runtime-db partition** (`:rf.db/runtime`); a `:db` return cannot touch it, and a `:rf/runtime` app-db root is a hard error | a wholesale `{:db fresh}` replace is now safe; a `:db` carrying a retired `:rf/runtime` key throws `:rf.error/legacy-runtime-root` (#3) |
| effect maps accepted top-level `:dispatch` etc. | effect maps are `{:db … :fx …}` **only**; other top-level keys are silently ignored | a missed M-8 fold compiles and **does nothing** (#4) |

The common thread: v2's stricter contracts and its two-partition runtime model (app-db + a framework-owned runtime-db) are *correct* design choices (they buy atomic revertibility, SSR survival, and tooling visibility — and make the old wholesale-replace clobber structurally impossible), but they relocate the remaining failures from "won't compile" to "compiles, boots wrong." The live-introspection smoke-test is the cheap insurance.
