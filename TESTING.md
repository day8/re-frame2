# Testing policy

## The challenge

re-frame2 has many kinds of tests, and they have very different costs. Fast ones (CLJS unit, JVM unit, drift checks) take seconds. Expensive ones (browser feature matrices, MCP live conformance, template emitted-app smoke) take many minutes — sometimes a small multiple of that when several stack.

Running everything everywhere makes PRs slow and the dev loop painful. Skipping the expensive ones at the wrong time lets regressions through to release. **The whole point of this document is the system we use to manage that tradeoff.**

## Kinds of tests

This table is also the command catalogue: each kind names the command that runs it (npm scripts run from `implementation/` unless noted; full script definitions live in the `package.json` files).

A checker joins the chain by being appended there and nothing makes this paragraph notice, so read the npm script rather than trusting any enumeration here to be complete. Each link runs its own `--self-test` first and then the real read. The chain is: the optional-module reachability check (nothing declared optional is reachable from the artefact’s public door, and no `src/` namespace requires UIx or the bench tree — the `bench tree` row is what SEALS the package against its own measurement harness, which lives out at `bench/fresco/`); and the guide-sample naming check (rf2-r5iy7, `check_guide_samples.py`: every `alias/verb` a fenced block under `docs/core/fresco/` names resolves to a source definition). The guide-sample check pins NOTHING and imports no hashing primitive, so a guide prose edit — or a sample edit naming no new verb — is a one-file change with no roster to regenerate. They share a script because they share an input surface and a schedule; giving each its own would cost a workflow step or a declared scheduling hole and buy nothing. The name says *invariants* rather than *freeze* for that reason (rf2-ibje). **One lesson from the retired freeze gate is worth carrying, because the shape recurs**: it hashed each DONOR file and then merely checked that the corresponding package path EXISTED, so a value could change in the package and the gate still report zero failures — while this table and `test.yml` presented it as proof the two trees agreed. A gate that hashes one side of a claimed equality must reconstruct and compare the other; a hollow gate advertised as proof is worse than no gate. |
| **Fresco controlled-input, three engines** — `test:fresco-controlled` | expensive | Invariant I15 (the §4.2 accept / refuse / normalise / reset policy family) driven in real Chromium, Firefox and WebKit — 97 checks per engine and 13 mutation teeth. Three engines because the mechanism is made of what engines differ on: caret and selection restoration, composition carriage, and the order a discrete event's work is flushed. What it buys over the value-level assertions was **measured, not assumed** — three deliberate regressions (a deferred converge, an end-of-string caret restore, a pre-flush record handed back) were driven through the whole matrix and ALL THREE were caught by the caret rows and by nothing else, because React's own end-of-event restore repairs value errors inside the same discrete event. The runner keeps two verdicts apart: REQUIRED rows are the spec's assertions, RECORDED rows are conduct it measures — and recording is not a way of not asserting, because the runner COMPARES recorded rows across engines and reds a divergence no `NARROWINGS` entry names. Its coverage floor is **structural rather than a total**: `REQUIRED_SECTIONS` pins the exact set of thirteen section names with the checks each banks (97 today) and `REQUIRED_RECORDS` pins the keys every recorded row carries, so deleting a witness whole reds, and three engines that all recorded nothing red too instead of agreeing perfectly. A flat check-count floor cannot do that: against a full engine's 55 checks and a floor of 50, either three-row section could be deleted entire and the run would still bank 52 and exit 0. The 13 teeth are what prove that verdict logic can itself fail, and they all bite before any browser launches. The gate's own header carries a **behaviour-by-engine table**, which is how a behaviour asserted on only one engine — or dispatched by the page helper in every engine and asserted in none — is found rather than assumed; every enumerated behaviour is driven in all three. **A row earns its place by answering "what narrowing would let this pass while the law is broken?", not merely "did it run?"** Two rows are narrowed for exactly that reason: the mid-composition revision sits on `revision-strict`, a REFUSING field where the reset's target and the composing draft are different strings (on the accepting field they are the same one, so neither conduct could red), and `:tb/arm` resolves its event at arm time and shows it, so BOTH arms are witnessed in the turn they are clicked instead of one being waited out and the other assumed. The composition-guard sabotage the acceptance names has been run rather than reasoned about — `composing-input?` replaced by `false` turns WebKit red on the first composing update, and the header quotes it. CI arm: the required `cljs-fresco-controlled` job, per-PR on the `fresco_controlled` surface (rf2-ga8m). |
| **Fresco HMR contract, three engines** — `test:fresco-hmr` | expensive | The HMR contract witnessed through a **real** shadow reload, and the only gate in the repo that drives one. It runs `shadow-cljs watch :fresco/hmr-testbed` — not a compiled bundle over http-server like every other browser gate, because a compiled bundle cannot hot-reload itself — rewrites one marked line of a real source file, and lets shadow recompile, push the module, re-evaluate it and fire `^:dev/after-load`. Each save is confirmed by the NEW source literal appearing on screen, which is what separates *shadow carried code* from *a hook fired*: a counter alone would be satisfied by an after-load hook running against the module it already had. 45 real reloads and 153 checks per engine, in Chromium, Firefox and WebKit — including the split region's two sections (rf2-y5x6j, rf2-iq0a), which carry one raw React island through `react/memo`, `react/lazy`, a `:ref`, `defhost` and `[:>]`, and read the LOADER COUNT to establish that a save re-mints the lazy head and the chunk is fetched again. What it buys over the package's Node HMR suites is exactly what the #7755 audit named: those call `collector/mint-view!` directly and drive the commit and release seams by hand, so they can catch neither drift between `defview` macro expansion and a real shadow reload nor a renderer that fails to run old-generation cleanup on a type replacement. It keeps the same two verdicts apart as its controlled-input sibling — REQUIRED rows assert, RECORDED rows are compared across engines and red an unnamed divergence — with a structural floor (`REQUIRED_SECTIONS` / `REQUIRED_RECORDS`) rather than a check total, and its mutation teeth cover the HOT-LINE rewriter as well as the verdict logic, because a gate whose "save" silently stopped editing the file would report a perfectly green run in which nothing ever reloaded. Served on shadow's own `:dev-http` **port 8061** so the document and the devtools websocket share an origin — the one respect in which it cannot follow the resolved-port convention. CI arm: the required `cljs-fresco-hmr` job, per-PR on the `fresco_hmr` surface (rf2-hic-015). |
| **Skills structural** — `skills-structural` job | fast | Skill manifests + structural content stay valid against the schema. |
| **Browser unit** — `test:browser` | medium | DOM-dependent tests only (`*_dom_cljs_test.cljs`): real React mounts, context tier, browser-only runtime features. **It is the ONE browser DOM lane**: `:browser-test` selects every `*_dom_cljs_test` namespace outright. What `_browser-dom-lane-partition.test.cjs` proves on every PR is that the selector reaches every DOM namespace, and that the lane has an executor CI is held to running — without which a lane could pass by executing nothing (rf2-mf4uy). One configured value, two sequential phases: `BROWSER_TEST_TIMEOUT_MS` (360s, rf2-15047) bounds the `page.goto` navigation **and** the wait for the cljs.test summary that follows it, so raising it moves both, and a timeout names the phase that fired rather than leaving the navigation on Playwright's undocumented 30s default — a ceiling no lane budget could reach (rf2-dczpv). |

## Test surfaces and their owners

Each surface has one owner and one purpose. Real bugs land in framework contracts, adapter wire-up, and tool lens behaviour — not in "this example mounted and clicked" — so coverage lives with the owner and examples stay clean.

| Surface | Owner / purpose | Tests? |
|---|---|---|
| `examples/` | Humans — learning + demonstration. | **No.** Test-free by ruling; the compile gate covers build health. |
| `implementation/adapters/<name>/testbed/` | Per-adapter smoke. | Two `spec.cjs` smokes (Reagent / UIx) via `test:adapter-smokes`; the reagent-slim testbed is driven by its dedicated runner (`test:reagent-slim:smoke`). |
| `testbeds/` | Framework feature-matrix substrates (Xray / Story / pair-mcp observation targets). | CLJS/JVM unit tests only — no per-testbed browser specs. |
| `tools/xray/testbeds/`, `tools/story/testbeds/` | Tool-owned scenario substrates. | Yes — the tool's feature gates drive them. |
| Per-artefact `clojure -M:test` | Contract protection (the spec is the artefact). | Unit, not smoke. |

Don't grow example-level specs, and don't overload examples with internal canaries.

## How we manage the cost

- **Cheap tests** run on every PR + every checkin. No conditional gating.
- **Expensive tests** run only when needed — gated by a **changed-surface classifier** on PR CI, by **full sweeps** nightly, and by **release gates** before tagging.
- **Expensive browser gates run in two tiers**: a high-signal **PR smoke** on the critical path, and the **full sweep** nightly. The nightly set is a strict superset, so the smoke never becomes the only coverage. **Superset of the PR gates, not of every gate the classifier can arm** (rf2-mvq7): a surface-armed job that is skipped on a main push reports the same colour as one that passed, so a gate with no unconditional arm anywhere is invisible on main until some PR happens to touch its surface. `expensive-tests.yml` carries the narrow-armed gates too, and the four it deliberately leaves out are named in its own `DECLARED HOLES` comment with the exposure each one accepts — the `unscheduled` idiom of `check_gate_scheduling.py`, applied to cadence instead of existence.
- **Per-tier scenarios** package these into named workflows so contributors know which gate they're in.

The classifier maps "what files changed" → "which expensive jobs fire." The full matrix runs nightly and on release candidates regardless of the diff. Skipping the wrong gate at the wrong time is the failure mode this system exists to prevent — **Placement decision dimensions** below is the frame for placing a new test.

## The 4 tier scenarios

1. **Agent pre-checkin** — `scripts/test-fast-pr.sh` plus the surface-specific commands for the files touched (find them in the Kinds table). The spine tiers itself the same way PR CI does: it reuses the changed-surface classifier below to decide which runtime suites its diff owns (`implementation_jvm` → the JVM artefact suites; `cljs_node_test` → the npm/CLJS/JS-harness/isolation suites), runs the documentation gates when the diff touches documentation content, and keeps the cheap static/drift checks always-on. A documentation- or EP-only diff therefore runs static + doc gates and skips every runtime suite; `--all` (or `RF2_FAST_PR_ALL=1`) runs the complete spine regardless (rf2-r6x1t).
2. **PR CI** — `.github/workflows/test.yml`. Always: lockstep + skill/MCP drift, core JVM (in both postures — `jvm-core` with dev instrumentation, `jvm-core-prod-gate` without it), CLJS node integration, JS harness self-tests, docs link validation on docs PRs. Expensive jobs fire only on their changed surface, and browser gates run their smoke tiers.
3. **Nightly / manual** — `.github/workflows/expensive-tests.yml`. The rigorous browser/bundle matrix, unconditional all-examples compile, full Story/Xray sweeps, template smoke, live MCP conformance, and the perf User-Timing emission lane (wired by rf2-a9oic, having run nowhere at all). **It reports its own failures** (rf2-6sg25): a final job opens, edits and closes one tracking issue, alerting on a change of failure *signature* rather than on failure, so a long outage costs one notification instead of one a night. That matters more than it sounds — the whole two-tier split rests on this workflow being the system of record, and with nothing firing when it reddened, eighteen of thirty consecutive runs failed unnoticed, thirteen of them in a row.
4. **Release** — `.github/workflows/release.yml` plus the latest green expensive run on the release candidate.

**Every gate command has a scheduled home, or says why it does not.** A gate is *defined* in `implementation/package.json` and *runs* in a workflow, and nothing held those two in step: `npm run test:perf-bundle` existed, did real work, and appeared in no workflow at all, so its positive control had never once been executed by CI (rf2-eegpw). `scripts/check_gate_scheduling.py` closes the class rather than the instance — every `test:*` / `bench:*` / `build:*` command must be reachable from a `npm run` in some workflow (the closure is walked, so a chaining script counts for everything it chains), or carry a declared disposition whose premise the checker then verifies: `covered-by` names a script that must itself still be scheduled, `ci-runs-it-directly` names a literal the workflow corpus must still contain. A gate that is neither is a hard failure, so the next unscheduled gate is caught on arrival. **`build:*` is in scope as well as `test:*` and `bench:*`** (rf2-rbdc), and the omission it repaired cost what the checker exists to prevent: `build:fresco-release` is the fresco artefact's only `:advanced` compile — the one place Closure renaming, externs inference and DCE-sensitive interop are decided — and it stood with no script and no job while nothing could report it, because a `build:` name was unreportable however load-bearing. A `shadow-cljs release` exits non-zero on a Closure error, so these are compile gates wearing a different prefix. Measured rather than assumed: deleting `build:fresco-release`'s step from `test.yml` reds the checker. It runs **per-PR**, always-on, in `test.yml`'s repo-invariant job and in the fast-PR spine (rf2-k78o2) — it measures under a second, and a workflow edit is exactly the change that can unschedule a gate while touching no surface the classifier tiers on.

Its first census found four unscheduled gates, not the one that raised it — among them a build *named* for the nightly that was in no nightly, and a whole warm-edit proof referenced by its own npm script and by nothing else in the repo. All four were given homes; the class is what the checker holds closed now.

**Run a gate green before scheduling it, and read a red gate as a possibly-red *gate* rather than a red artefact.** `test:schemas-bundle` was measured cold before wiring and came back **red**: both probes at 124.9 KB gzipped against a 100 KB ceiling. That read as a 25% bundle regression and was not one. The schemas surface had grown 1.0 KB in three months while `cljs.core` + `re-frame.core` grew 43.8 KB, and the 100 KB figure had been transcribed from a Reagent/React harness row onto a bare probe that measured 50.3 KB — never derived from the thing it guarded. The gate was asserting an **absolute** size where Spec 010 §Bundle cost budgets a **marginal** one, so it fired at the schemas artefact for growth outside it. It was neither threshold-bumped nor wired red: the ceiling was replaced with a two-sided margin between a core-only control build and the schemas probe, the quantity the spec actually budgets (rf2-kybsf, rf2-v4o7e). **A gate earns a schedule by asserting something true, not by being given a number it can clear.**

**The Story/Xray two-tier split.** The `story-xray-browser` PR job runs `test:xray-feature-gate:smoke` + `test:story-play-scripts`; the full sweep runs nightly. The dominant cost is testbed compilation, so both tiers share a keyed shadow-cljs compile cache that any source change busts.

One exception, and it is the exception that keeps the split honest (rf2-65ajl, rf2-9n2cv): a gate that is nightly-only cannot be *changed* safely, because the PR changing it runs nothing that loads it. Two nightly commands therefore also run at PR time, but only on the PRs that edit their own definitions:

- `test:story-feature-load`, on its two Playwright spec modules (`tools/story/test/story_feature_load.cjs`, `story_browser_scenarios.cjs`) or the run/serve orchestration that stages them — the `story_full_gate` surface.
- `test:story-static`, on the gate script it *is* (`implementation/scripts/check-story-static.cjs`) and the build script that gate spawns (`story-build.cjs`) — the `story_static_gate` surface.

Ordinary Story/Xray runtime changes are untouched and keep the cheap smoke path; the nightly sweep remains the system of record for the full matrix.

The Xray full matrix is deliberately **not** a third such exception. `test:xray-feature-gate:smoke` — a command the PR job already runs — loads and validates the whole of `tools/xray/testbeds/feature_matrix/scenarios.cjs`, so the file cannot merge unparsed; what runs nightly is the non-smoke *rows*, which is this policy working as designed rather than a hole in it. When adding an Xray scenario, tag it `smoke: true` only if it earns a slot on every PR **and** loads an already-staged smoke surface; everything else is nightly by default. A non-smoke scenario does not run again until that night, so before merging one that is new or materially changed, run the full gate locally with `cd implementation && npm run test:xray-feature-gate` and note the result in the PR. The gate fails loud if the smoke set is ever empty.

## Test authoring policy

**New tests register and carry an explicit frame** — `{:frame …}` on dispatch/subscribe or a `with-frame` scope, per Spec 002 §Frame target resolution: frame identity is *carried, not found*. The `ensure-default-frame!` fixture is retained solely for the older suites that already use it and is **not an idiom to copy**; conformance fixtures must never dispatch framelessly expecting default stamping.

**Every app in the shared node test bundle namespaces its URL paths.** Route ids are namespaced keywords and cannot collide; route *paths* are plain strings in a process-global registrar, and `npm run test:cljs` loads a dozen applications into one process. Two apps that both claim `/` share a single match-table entry, and ties go to the earlier registration — so the first one loaded wins every URL, the later is unreachable for URL ingress, and the breakage surfaces in a suite that has never heard of the offending app, naming its routes (rf2-wqnl; it cost twelve RealWorld assertions in PR #7920). Any app or witness added to the shared bundle therefore puts its paths under a distinct leading segment — `/slice`, `/fresco-todo` — and the bare top-level paths stay with the teaching examples that already hold them. The prefix earns more than it looks: distinct leading literals can never co-match, so it also forecloses the subtler overlap of one app's literal sitting under another's capture, which exact-duplicate detection cannot see. Enforced by `implementation/routing/test/re_frame/routing_path_census_test.clj`, which censuses every namespace-load-time `reg-route` under `examples/`, `testbeds/` and `implementation/fresco/test/` — including one registered from a `register!` function called at namespace load, and one whose id is a `def`'d symbol — and fails when two ids share one canonical path, naming both with their source coordinates (rf2-p5og).

**Story-as-test runs headless first.** Variants and inline plans run through the `:headless` runner (fast, JVM/node, no browser) for state/effect/schema/trace assertions — consistent with the CLJS-unit-tests-not-Playwright default; reach for a browser-tier assertion only when it genuinely needs browser behaviour. Every gate that runs plans defines a `:cannot-run` policy (fail / inconclusive / route to a richer runner); the headless default reports browser-only assertions as **inconclusive with a count**, never a silent pass. The dedicated capability-routed (:pixels / :a11y-engine) browser-tier gate itself stays deferred (rf2-315cf) until a compound first-of trigger fires: the first committed authored variant/inline plan that intentionally carries a browser-only assertion wires a nightly gate in `expensive-tests.yml`, or the first genuine visual/a11y regression that the structural check + existing Story/Xray browser gates miss escalates it to a changed-surface PR gate (rf2-a0t1z5). Failed runs can emit a replayable `:rf.test/run-artifact`. The authority is [`tools/story/spec/017-Testing-Story.md`](tools/story/spec/017-Testing-Story.md) §CI policy.

**Always-on error categories carry a change-time evidence ratchet.** The Spec 009 `always-on` catalogue promises that a category's real emit site survives a release build — `:advanced` + `goog.DEBUG=false` for a CLJS-reachable site, or the debug-disabled JVM runtime for a JVM/SSR-only one. Nothing structural binds a catalogue row to that promise, so the class can regress silently: a category can be catalogued always-on, pass the synthetic conformance gate, and still emit from a `goog.DEBUG`-gated (or purely diagnostic) real site. The `drive-category!` gate in `always_on_axis_conformance_cljs_test.cljc` stays deliberately synthetic — it drives fabricated payloads to pin the listener registry's fan-out, which is its job, not a re-derivation of each real emit site. Rather than a blanket production-build proof across all 43 categories — thousands of speculative test lines that still could not catch the next arrival, since it lands with new code — we place proof at the change-time moments where it becomes cheap and mechanical. Four obligations do that work:

1. **The existing 43 categories carry no backfill.** The exhaustive `rf2-hk3eb` emit-site walk — all 43 always-on rows walked to their real sites, zero gated — is the point-in-time baseline. Do not open a retroactive production-test quota for the 26 categories with no `*_elision_prod_test.cljs` assertion today.
2. **A new or promoted always-on category proves itself in the same change.** That PR must (i) drive the real emit site in a dev-build test that asserts the `:errors` listener — the channels are separate registries, so this is what catches a wrong-channel emit — and (ii) prove the production posture, with a real `:advanced` + `goog.DEBUG=false` assertion for a CLJS-reachable site or a debug-disabled JVM integration assertion for a JVM-only one. For the JVM half, "debug-disabled" now means the `jvm-core-prod-gate` lane — a real `-Dre-frame.debug=false` JVM — not a `with-redefs` of `interop/debug-enabled?`, which cannot reach a gate the framework decided at load time (rf2-f8x2i). Reuse an existing prod-elision fixture when it already exercises the branch, and watch the shared prod-elision bundle's composition premises (see the `routing_scroll_always_on_elision_prod_test.cljs` docstring) when a new artefact require changes what that bundle pulls in.
3. **Refactoring an existing always-on emit site needs new production proof only when it moves the gate.** A fresh proof is required when the change moves or wraps the call chain across a compile-time / `goog.DEBUG` gate, or changes which always-on seam is reached; payload-only, wording, and unrelated refactors incur none. The PR states that the always-on call is not transitively inside a `goog.DEBUG`-derived gate, and the reviewer checks the gate chain by the `rf2-hk3eb` method.
4. **A production-silence bug fix always pins the regression on the fixed surface's host.** Applying obligation 2's split to the fix: a CLJS-reachable surface carries the focused per-surface `*_elision_prod_test.cljs` pin — the `rf2-2hkfy` precedent (`routing_scroll_`, `teardown_`, and `frame_ops_always_on_elision_prod_test.cljs`); a JVM/SSR-only surface carries the focused debug-disabled JVM integration assertion, since no `.cljs` test can reach that emit site. The three `*_elision_prod_test.cljs` files are the CLJS-branch examples, not a universal filename requirement.

This axis is revisited at API-freeze / external-alpha prep, alongside the facade-export audit, once real production consumers exist to protect — or earlier if a defect of this class ever gets past the ratchet.

## Required checks the fast-PR spine does not run

`scripts/test-fast-pr.sh` is a **spine, not a mirror**. `PASS fast PR spine` is entirely
compatible with a red required check, and three workers in a row have proved it — each
one green locally, each one red in CI on a *different* check, each costing a round trip.
Do not read the list from here; derive it:

```bash
python scripts/check_fast_pr_gap.py --list    # every unrun required check + its local command
python scripts/check_fast_pr_gap.py --brief   # the digest the spine appends to its PASS line
```

It is derived rather than written down because a written list would already be wrong: new
required steps land in `test.yml` faster than prose tracks them — two did on the day the
gap was first catalogued. Three properties of that gap are worth carrying in your head
before you read the report.

**There are three required status contexts, not one.** `All required checks passed`
(`test.yml`), `Lint required` (`lint.yml`) and `Docs required` (`docs.yml`) each aggregate
their own `needs:` list. The spine has lanes only in the first — `clj-kondo`, Splint,
ESLint and the public-API manifest drift-check are all required, and none of them is in
any tier of the spine.

**A required check can be a step *inside* a job the spine runs, and it need not be a
test.** The spine's skipped-tier enumeration cannot see that class: the tier is not
skipped and the step is not a suite. The live witness is `npm run build:fresco-release`,
the `:advanced` / `goog.DEBUG=false` compile of the Fresco consumer app: it is a step of
the `cljs` job, and the spine matches that job through its node-test run while never
building that bundle — so a green spine is entirely compatible with a red Closure compile,
reported under a *job* display name that reads like a test suite. A worker reading such a
red goes looking for a failing test that does not exist, which is why the report names the
**check** and prints what it actually runs.

**One invariant checker is CI-only on purpose.** Nearly every required
`python scripts/check_*.py` invocation has a local lane — twenty-nine in the spine's
always-on block (mirroring `verify-skill-mcp-drift` and `verify-readme-links`, which CI
runs unconditionally) and eight in the documentation tier (mirroring `docs.yml`'s
`docs_surface`-gated `build`) — and together those cost **6.4s** (rf2-ejm7m).
`check_retired_image_keys.py --verbose` costs **37.7s by itself**, more than double the
spine's whole documentation tier, so it stays in CI and the report still names it. That is
a measured decision rather than an oversight (rf2-e1xx0 tracks making it fast enough to
join the others, after which it leaves this report with no list edited anywhere).

**A local `clj-kondo` pass proves nothing unless it is the pinned build.** CI installs an
exact version and fails on ERROR level only, warnings staying informational; two versions
disagree about which findings are errors, and this project's Windows checkout has
reproduced exactly that — 0 errors locally on the line CI failed, and 10 different errors
CI never reported. The report prints the pin, read from the workflow's own installer step
so a bump cannot leave it stale.

The JS harness gate is one command, `npm run test:scripts`, and the spine runs exactly
that, as CI does. One discovery command rather than hand-maintained rosters run in
sequence: a roster you can run half of is a class of error removed rather than guarded.

**Blast radius**: a change to either workflow file, the classifier script, or `TESTING.md` sets every output `true` — anything that re-tiers the matrix must re-run the matrix. `implementation/core/*` fans out to almost everything (core regressions can break every downstream invariant), deliberately excepting the two Playwright gates noted above.

**A ledger that claims a lane must schedule it** (rf2-49upn). A Python-only always-on job can prove the *static* half of a coverage claim — that a real assertion reaches each row's fixture, from a lane serving every cell the row claims — but never the *dynamic* half, that the assertion passes, because it runs no suite. That half is the exit code of some other job entirely. **So when a Python-only always-on job certifies a claim that some OTHER job executes, arm the executing lanes from the certifying document, or the certificate can be issued on a commit where nothing ran.**

**Adding a new artefact directory needs two matching changes**: a classifier rule (which outputs the path lights) and a workflow gate whose `if:` reads them. Either side missing is a silent hole — code can land that mutates a surface no PR-time job watches. When in doubt, over-classify — but set only the outputs whose jobs the artefact's tests actually exercise, since coarse rules clutter the matrix with `skipping` entries.

To see exactly what a diff fires, run the script — it is executable truth, and takes `--all` or an explicit path list:

```
.github/scripts/report-changed-surfaces.sh implementation/core/src/foo.cljs
.github/scripts/report-changed-surfaces.sh --all
```

**The local fast spine reuses this same script**, not a second map: `scripts/test-fast-pr.sh` gathers its diff (committed vs `origin/main` + staged + unstaged + untracked), feeds the paths to the classifier as explicit args, and gates the JVM artefact suites on `implementation_jvm` and the npm/CLJS/JS-harness/isolation suites on `cljs_node_test` — the same outputs test.yml's `jvm-core` and `cljs` jobs gate on. Local selection stays aligned with CI by construction; run `scripts/test-fast-pr.sh --plan` to see the tier decision for the current diff. Which *artefact* suites run inside the JVM tier is the spine's own narrowing (core plus the artefacts the diff touched) rather than a mirror of CI: `implementation_jvm` arms every per-artefact CI job at once, so the spine's selection is always a subset of CI's, never a divergence from it.

## Diagnostic / skip-ok gates

Some checks intentionally exit 0 when their preconditions are absent. They are diagnostic, not coverage.

| Gate | Why skip-ok |
|---|---|
| Adapter JVM classpath probes (`jvm-{reagent,uix}`) | Adapter namespaces are `:cljs-only`; the probe proves deps + classpath wiring even with a zero-test alias. Two sibling jobs scheduled alongside them are **not** skip-ok and must not be read as probes: `jvm-reagent-slim` runs the component-shape detection contract, and `jvm-adapters-test-react` runs the Test-React lifecycle suite (35 deftests / 157 assertions — the adapter is pure CLJC by design, so its `.cljc` tests are real JVM coverage). The two do not sit on the *same* gate: `jvm-reagent-slim` is on `adapter_diagnostic` alone, while `jvm-adapters-test-react` is on the **superset** — a disjunction of `adapter_diagnostic` with `test_react_jvm` (rf2-6r9j.87). Real coverage for reagent/uix: the adapter smokes + per-adapter CLJS unit tests. |
| Pair live-overflow without nREPL (`mcp-conformance-re-frame2-pair`) | Exits 0 with a SKIP marker when `$SHADOW_CLJS_NREPL_PORT` is unset — so the SKIP path itself is exercised every run. Real coverage: the hermetic-suite step that follows. |

Never treat a passing skip-ok diagnostic as evidence the behaviour was covered; the real coverage is the changed-surface, nightly, or release gate.

## Retiring CI surface

The Freehand CI lanes came off in three staged PRs and the subject is gone — `freehand-bench.yml`,
`freehand-conformance.yml` and `implementation/freehand/` are all deleted. The *method* is what survives, and
it is the reusable part.

**The unit of a retirement plan is a trigger: an event somebody can check, never a date.** A stage with no
checkable trigger is not a stage, it is a wish. Order the stages by dependency rather than by preference — the
lane carrying a live coverage obligation comes off before the merely advisory one, which is the reverse of the
intuition. Each stage lands as its own reviewed PR, and a plan authorises no deletion by itself.

**Retire a certifier last.** What a certifying job alone proves — id uniqueness, that each named fixture
exists, that each cited anchor resolves, that a real assertion reaches that fixture from a lane serving every
cell the row claims — is proved nowhere else the moment it goes. Deleting it may strand nothing *required* and
still be a genuine loss.

**A prose trigger is necessary and not sufficient, because a coupling can be a BUILD coupling that no prose
survey sees.** The conformance corpus was read at *macro-expansion time* by suites in the tree being deleted —
deliberately, so the JVM and ClojureScript suites asserted against the same bytes, and so that an unresolvable
fixture failed the COMPILE loudly rather than yielding an empty table that would make a suite pass vacuously.
Deleting the corpus while that tree still stood would have reddened three required jobs. Survey for
compile-time reads, not only for citations.

**A roster that spans two trees does not retire cleanly with one of them, and the survivors are invisible
precisely because the gate that named them is the gate being deleted.** A nineteen-namespace compile roster
lost seventeen with its tree; the other two lived elsewhere and were compiled by nothing until they were
re-homed.

**Check that a census command returns something before believing a zero.** A differently-shaped pathspec for
the same question returned no output at all on at least one supported checkout while the true count was 68. On
a trigger that authorises a deletion that failure direction is fail-open: an empty result reads as "the
condition is met". Cross-check any zero against a plain directory walk, and prefer two instruments that agree.
A repo-wide `rg` census without `--hidden` silently omits `.github/` — which is how a retirement sweep reports
a surface clean while a required job still names the thing being removed.

**Count the right quantity, and expect more than one.** The last stage turned on *external* references to an
id: an `FH-*` id was an ADDRESS in the normative spec, and it stopped being one when the spec stopped
describing the subject. Worded instead as "no page under `spec/` cites the id" the condition could never have
become true, because the index is where those ids were *defined* — a trigger satisfiable only by the deletion
it was supposed to authorise. And the recorded figure was not the only quantity that mattered: a page linking
the index without naming an id was invisible to it, so a sweep satisfying the recorded figure literally would
still have left a required check red. The measure that holds is the broader one.

**`portability.yml` was audited alongside those two and is in no stage.** All three of its jobs enforce live
recorded rules over the whole tracked tree. Its `ai/` ratchet has reached its declared end state —
`git ls-files ai/` is empty — and the ratchet is now the only thing holding it there, which is an argument for
keeping it rather than for retiring it.

## Placement decision dimensions

Do not classify a test on one axis — a slow test is not automatically optional, and an essential test is not automatically global PR CI. Combine:

| Dimension | Question | Implication |
|---|---|---|
| Scenario | Pre-checkin, PR CI, nightly, or release? | A test can be mandatory at checkin and release without running on every unrelated PR. |
| Speed | Measured wall-clock, including setup? | Fast high-signal → PR CI. Slow → changed-surface, local, nightly, or release. |
| Essentiality | What invariant does it protect? | Essential invariants must be covered somewhere mandatory — not necessarily always-on. |
| Changed surface | Which files can plausibly break it? | Select tests from the diff's impact radius, not a fixed suite. |
| Dependency fan-out | Is the change upstream of other surfaces? | Core and shared substrate fan out broadly; leaf changes run their owning gates. |
| Unique signal | What would this catch that cheaper tests miss? | Keep expensive tests with distinct signal; demote duplicates. |
| Fixture role | Example, adapter smoke, or tool testbed? | Coverage lives with the owner; examples carry no canaries. |
| Naming | Does the name reveal the policy role? | A `:diagnostic` / skip-ok command must not read as real coverage. |
| Skip semantics | Can it exit 0 with prerequisites absent? | Document as skip-ok; never count a skip as coverage. |
| Failure quality | Is a red actionable from CI logs? | Red names the contract, owning surface, and repro command. |
| Security boundary | Does it touch redaction / escaping / egress? | Gets an **adversarial-property** net in the `security/` tier — hostile corpus + generated shapes, verified to go RED on revert. Extend the matching security namespace when touching such a boundary. |

Before adding any new Playwright, bundle, MCP, Story, or Xray gate to PR CI: prefer one small fixture that proves the owning contract over full-app sweeps; a minimal counter is enough for an adapter smoke; if the timing or unique signal is unknown, measure first.

| Test kind | Typical placement |
|---|---|
| Fast essential | Every PR/checkin. |
| Fast nice-to-have | Usually every PR unless noisy or duplicative. |
| Slow essential | Pre-checkin for relevant changes, changed-surface PR CI, nightly, release. |
| Slow nice-to-have | Local, nightly, or release — off the PR critical path. |

## Spec-impl-pair convention

Top-level `spec/*.md` has **no classifier rule**: a spec-only PR runs only the always-on jobs. This is intentional — a blanket `spec/* → mark_all` would re-run the rigorous matrix on every typo fix. The expected pattern is the **spec-impl-pair convention**: a spec change ships in the same PR as the impl/test change realising it, so the impl edit fires the right surface and the spec rides along. Spec-only PRs are fine for pure normative refinements; if a spec change implies any implementation change — even a test — pair them, and if reviewers want the rigorous matrix against a spec-only PR, run `expensive-tests.yml` before merge. First regression through this gap triggers a surgical per-spec-file rule, not a blanket one.
