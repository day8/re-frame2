# Enhancement proposals (EPs)

Enhancement proposals record re-frame2 design decisions and their rationale, following the Python Enhancement Proposal model. Accepted proposals guide changes to the specification and implementation. Resolved proposals remain as historical records, with dated notes for later decisions.

The EP process itself — types, status lifecycle, durability rules, and the EP-worthiness bar — is normative in [EP-0009](EP-0009-the-ep-process.md). This README is only the index and summary.

## Authoring a new EP

Copy [`EP-template.md`](EP-template.md) to `EP-NNNN-<slug>.md`, fill it in, and add an index row below. The template encodes the active-process rules so a new EP follows them by construction: `Status:` is a [controlled lifecycle](EP-0009-the-ep-process.md#statuses) (not free text), and `Type:` is `standards-track` or `process`. Graduation is per-type — standards-track into `spec/`, process into its named normative home (which may be the active EP itself). The full process — including the EP-worthiness bar, bidirectional successor records, and [document conventions](EP-0009-the-ep-process.md#document-conventions) — is normative in [EP-0009](EP-0009-the-ep-process.md). `scripts/check_ep_status_sync.py` is the mechanical gate (status/type grammar, lifecycle metadata, supersession targets, and README/header sync).
