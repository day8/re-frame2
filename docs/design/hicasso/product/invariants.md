# Hicasso invariant and capability ledger

One page to check a change against: every invariant the product commits to, every capability and the rent it pays, and the provisional facade as the specification currently spells it.

Nothing here is new. Every row is transcribed from the [product specification](specification.md), the [design laws](lanes/design-laws.md), the [public-language lane](lanes/ergonomics-api.md), or the [decision brief](decision-brief.md), and cites its owner. **Where a row and its owner disagree the owner governs and the row is the defect** — fix the row; questions are not settled here.

Cite key: `§n` is a [product specification](specification.md) section; a capitalised word plus a number, such as *React 5*, is that numbered law in the named section of the [design laws](lanes/design-laws.md).

### The callback and frame-incarnation rule (rf2-hic-013)

**The rule.** A frame's public keyword id names an address, not an object. Destroying a frame and creating another under the same id produces a new incarnation, distinct by identity, and every operation minted against the predecessor — a captured bundle, a lowered callback, a retained handle — belongs to the predecessor for the rest of its life. Fired after the successor seats, such an operation writes nothing and refuses with `:rf.error/frame-destroyed`. **Where a delayed operation lands is fixed when it is minted, never when it is invoked**: an operation that resolves its target at call time resolves an address whose occupant has changed, which is a revival rather than a dispatch.

**What is witnessed.** `implementation/hicasso/test/re_frame/hicasso/reincarnation_routing_cljs_test.cljs` and its `_cells_` companion. The arm's frame-locked bundle obeys the rule — `:dispatch`, `:dispatch-sync` and `:subscribe` each refuse across the transition and fan exactly one always-on record, while an *unpinned* capture of the same shape does write the successor, so the refusal is the incarnation pin's doing and not an unresolved miss. On the committed side the teardown drops the cell's reaction synchronously and rebuilds it a macrotask later, and that deferred callback routes to the live incarnation when one exists and disposes exactly — zero cells, references and edges — when none does, which is [I5](#1-invariants)'s exact-teardown clause and [React 2](lanes/design-laws.md#react-and-ownership)'s *disconnect releases it* measured at the frame boundary.

**Two things the transition is invisible to, which is why the narrowing is worth recording.** `commit-basis` ties across a same-id reincarnation — its frame term restarts and neither of the other two is a frame fact — so the number React re-reads through `useSyncExternalStore` does not move when the successor seats, and no re-render is scheduled. Meanwhile the read path is address-directed on the public id, so a body re-run inside that window already paints the successor's value. Rendered markup is therefore a green instrument throughout, in both directions, and only the incarnation token, the memo's identity, the refusal record and the snapshot number distinguish *repaired* from *never broken*.

**Two open items, recorded rather than settled.** First, a **defect**: the ambient dispatch a lowered callback captures closes over the frame keyword and resolves its bundle when the callback fires, so a retained callback reaches whichever incarnation the memo happens to describe at that instant — refused if some earlier dispatch left the predecessor's bundle memoised, and a **silent write into the successor** if not. Exact eviction on destruction does not fix it and makes it universal; pinning the incarnation into the closure at mint time was measured to fix both branches. The remedy is a runtime change outside rf2-hic-013's surface, and the defect is recorded as a failing-when-fixed test in the routing suite. Second, a **question for the owner**: [React 3](lanes/design-laws.md#react-and-ownership) requires a render/commit tear to be *corrected before visible paint*, and the correction measured here is deferred to a macrotask, which carries no such ordering guarantee. Per this page's own rule the owner governs, so this is a defect in the runtime or a needed qualification in the law, not something this row settles.

### The HMR contract (rf2-hic-015)

**The rule, and it is the un-generous one.** A reload re-mints every boundary a reloaded namespace defines. `defview` expands to `(def sym (mint-view! "<ns>/<sym>" body))`, and `mint-view!` allocates a fresh component and a fresh memo wrapper on every call, so the element type at that position changes — **unconditionally, including for a view whose own source did not change**, because it is the module's re-evaluation and not the edit that re-mints it. React replaces the subtree outright. **The default expectation across a save is therefore a clean remount and never preservation**, and a view's name is an address rather than an identity, exactly as a frame's public keyword is under [rf2-hic-013](#the-callback-and-frame-incarnation-rule-rf2-hic-013)'s rule. The memo comparator is not a rescue and cannot be: React consults `areEqual` only when the type already matches.

**What is lost.** Everything React keeps on the fiber at and below the re-minted boundary — component identity, hook state, refs and the instances they hold, the DOM nodes themselves. In a developer's terms: focus, selection and in-flight composition in a controlled field, a child's `useState` inside a host, an active imperative host's live instance, and any uncontrolled value the DOM was holding. Cleanups run and the subtree is built again from nothing. This is React's own consequence of a changed element type, which [I6](#1-invariants) assigns to React; the runtime adds nothing here and rescues nothing, and no preservation machinery was built for it.

**What survives.** Application state, because it is not a React fact: app-db, the registered handlers, and the frame. Re-running `(rf/make-frame {:id …})` — the ordinary shape of a re-initialising `^:dev/after-load` hook — is idempotent replacement, and it is measured as such: the incarnation token is the same object afterwards, the seeded db is intact, and the arm's frame-op memo is untouched, so a bundle captured before the save still addresses the same incarnation. A reload hook that instead **destroys** the frame before rebuilding it leaves this contract for [rf2-hic-013](#the-callback-and-frame-incarnation-rule-rf2-hic-013)'s, where a same-id successor seats and the defect that freeze recorded — a delayed operation resolving its target when it fires rather than when it was minted — is live. Which of the two reload shapes a hook has is therefore worth knowing before writing one.

**The stale generation lets go completely.** Measured at the commit seam rather than in markup: after a save the key's cell carries exactly one reader and it is the *successor's* registration by identity; three successive saves still leave one; releasing the live generation returns cells, reader memberships, edges and the shared read-set entry to zero; and the hand-over does not depend on the order React commits the deletion and the insertion in. A count alone would not have settled it — a runtime that leaked the predecessor *and* failed to acquire for the successor also counts one — so the identity is asserted, and the bead's sabotage (withhold the predecessor's cleanup) is run as a real perturbation with its red and its restored green both asserted.

**Two windows a rendered assertion cannot see, and this is where the narrowing bites.** First, a save's re-registrations advance `registry-epoch`, a term of `commit-basis` that `make-snapshot` reads **only for a key no cell holds** — so one registration gets two correct answers: a mounted boundary's number ties, and an unrelated namespace's save costs the page nothing, while a boundary inside the render→commit gap sees the number move and its tear is corrected. Second, editing a `reg-sub` and saving drops the held reaction *synchronously* and rebuilds it **a macrotask later**; at the instant of the save the number React re-reads has not moved and no notification has fired, while a body re-run inside that window already answers with the edited subscription. Rendered markup is thus a green instrument on both sides of the window, and only the snapshot number, the notification count and the cell's reaction reference separate *repaired* from *never disturbed*. It is the same two-phase repair [rf2-hic-013](#the-callback-and-frame-incarnation-rule-rf2-hic-013) measured from the reincarnation side, reached here by the registry route — which carries that freeze's open question with it: a correction deferred to a macrotask has no ordering guarantee against paint, and [React 3](lanes/design-laws.md#react-and-ownership) requires one. Not settled here either.

**What is not measured, and is owed.** The three matrix rows that need a committing renderer — the focused controlled input, child hook state inside a host, the active imperative host — are **not** witnessed. The package's lane is Node: there is no DOM, and `react-dom/server` runs bodies without ever committing. What is measured is their single common cause, exactly and unconditionally, and the paragraph above on what is lost is therefore React's documented consequence of that cause rather than this project's own measurement. A browser suite owes those three rows; until one exists this row says so rather than implying otherwise. The witnesses are `implementation/hicasso/test/re_frame/hicasso/hmr_remount_cljs_test.cljs` and its `hmr_registry_cljs_test.cljs` companion.

### The ambient-read extent as enforced (rf2-hic-011)

**The rule, and the reason it is enforceable rather than aspirational.** `sub` is legal exactly during the direct synchronous execution of the active boundary body, helpers, branches and loops included, however deep and however dynamic; every crossing out of that extent refuses. The extent is a **dynamic** one and not a lexical one, and that is what makes it checkable: an ordinary helper two call frames down is inside it, and a closure written on the body's own line is outside it the instant something calls it later. Nothing about the shape or the position of the code decides. The only question is whether a boundary body is on the stack at the moment the read happens, and the runtime answers it by reading one slot that `run-once` sets in a `try` and clears in the matching `finally`.

**The legality matrix, as measured.** Every row is a test in `implementation/hicasso/test/re_frame/hicasso/read_extent_cljs_test.cljs`.

| Crossing | Legal | What decides it |
|---|---|---|
| A nested helper, at any depth | ✓ | Its reads are the enclosing boundary's, because the extent is the body's dynamic extent and a helper has no read set of its own to own them |
| A branch | ✓ | The arm that ran contributes its keys and the arm that did not contributes none — the edge is recorded where the read happens |
| A variable-length loop | ✓ | The collector window closes around the codec, which is eager, so a `for` is driven to exhaustion inside the window that wrote it |
| A render prop | ✗ | It is invoked during a render, but not during *this* body's render, and the runtime will not guess which render owns the read |
| An event callback | ✗ | It fires after the extent unwound. Its *dispatch* still works — the ambient dispatch is captured at lowering time on purpose — so the fence is on reads and not on callbacks |
| A promise continuation | ✗ | The microtask runs after the body returned |
| A timer callback | ✗ | Same, one macrotask later |
| A lazy sequence that escaped the render | ✗ | Realised with no body on the stack. The same carrier inside the window is the legal loop row above, which is the whole point of the pair |
| A module-load read | ✗ | A top-level form evaluates with no body, no frame and no root |
| An unforced `delay` at a boundary crossing | ✗ | Refused by the crossing walk rather than by the frame slot — see below |
| A deferral parked in a mutable reference and forced inside another body | **not refused** | The declared limit, below |

Each `✗` carries the stable shape I11 requires: a stable id, the source coordinate the runtime can state today, an actionable recovery keyword, and the offending query. The nine frame-slot rows refuse with `:rf.error/hicasso-sub-outside-render` and recover to `:read-inside-a-boundary-body`, and the message names `subscribe-once` as the sanctioned snapshot for handler and utility code. The tests assert the id, the `:where`, the recovery and the query as an exact map and assert only that the *prose* names the recovery route — freezing the wording would collide with [rf2-hic-007](specification.md#36-loud-stable-failure)'s error-shape constructor and rf2-hic-021's id catalogue, neither of which has landed.

**Two enforcers, not one, and the matrix needs both.** The frame slot cannot see a deferral forced inside *another* body's render, because a body genuinely is running there — the wrong one. `re-frame.hicasso.impl.codec/realize-deep` closes the structural half at the boundary crossing: it forces every lazy sequence reachable from a boundary's props inside the window of the body that *wrote* it, and it **refuses** an unforced `delay` with `:rf.error/hicasso-deferred-read-at-boundary` rather than forcing it, because forcing an author's explicit deferral would change what their program means. A `delay` the author already deref'd in their own body carries a computed value and crosses freely, which is the control that keeps the refusal from being "the walk refuses every delay".

**The residue neither enforcer reaches, measured rather than disclaimed.** `realize-deep`'s reach is the walk's reach: it descends into data structures, and a mutable reference is not one. A thunk an author parks in an atom is invisible to the structural pass, and if something forces it inside a different body's render the frame slot finds a frame and is satisfied — so the read is filed under a boundary that never wrote it, the page paints correctly, and the edge is wrong. The suite measures both halves of that: forced outside a render it refuses like every other escape, forced inside a foreign body it silently succeeds and the misattribution is asserted as the read set of the wrong boundary. If the hole is ever closed, that row is the one that goes red, which is what it is for.

**The reconciliation clause, and the number that carries it.** I7's third sentence says dynamic reads reconcile from the selected render without a general per-boundary dependency ledger, and there is indeed no ledger: a changed read set is a different cached entry, a different `subscribe`, and therefore a fresh registration whose held edge set is empty by construction, so the replacement *is* React's own cleanup plus its own re-subscribe. What is asserted is the outcome, per key — the key that stayed keeps exactly **one** reader, the key that disappeared keeps none, the key that appeared gains one — and the surviving reader is checked **by identity** to be the successor's. A count alone would not settle it, because a runtime that acquired for the successor without releasing the predecessor also counts one on the key that stayed.

**Every refusal was shown to fail first, and one perturbation changed the design of the suite.** Three perturbations were applied to the runtime, run, and reverted; none is committed. Removing the extent guard from `read-key!` reds nine rows — and it does **not** stop the escaped reads from throwing: they fall through to `subscribe-once`, which raises `:rf.error/no-frame-context` instead. A witness written as "something threw" would therefore have stayed **green** under the exact sabotage this freeze exists to catch, which is why every row asserts the whole ex-data map rather than the fact of a throw. Removing the unconditional scratch reset from `run-once` reds five rows, and it initially failed to red one of them: the row's follow-up body happened to re-read a key the previous body had also read, so the accumulated key was swallowed by its own expected set. The row now reads keys disjoint from the render that deferred into it. Removing the crossing refusal from `realize-deep` reds the `delay` row alone.

**What is not measured, and is owed.** Two deferral carriers have no witness here and are owed to a browser suite: a read deferred into a **React effect**, and a read deferred across a **Suspense retry or an Activity reveal**. Both are the same discriminator and neither is asserted, so this paragraph says so rather than letting the matrix imply completeness. The event-callback and render-prop rows *are* witnessed, at the exact lowered wrapper React would call, taken off the element the render emitted; what a browser would add there is the DOM's own dispatch and not the law.
