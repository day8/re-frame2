# The living requirements mine

The ledger the [use-case compass](specification.md#21-use-case-compass) requires. One row per recurring application job: what it is, how often the corpus actually does it, how it fails, where the answer lives, who is accountable, and what executable artefact proves it.

The mine exists to keep two decisions honest. Frequency justifies syntax — a job the corpus does hundreds of times may earn tier-1 spelling and standing cost. Rarity justifies an excellent escape or an optional module — never, by itself, a refusal. Absence from a census is evidence against universal syntax and standing cost; it is not evidence that the job is unimportant.

This is a seed, not a survey. The ledger's rows are exactly the [§7 coverage rows](specification.md#7-complete-use-case-coverage) — the spec owns that list, this file owns what is known about each entry.

## How to read a row

| Column | Meaning |
|---|---|
| Job | The application job, named exactly as [§7](specification.md#7-complete-use-case-coverage) names it. |
| Observed frequency | Counts from the revision-pinned census, or an explicit zero. A zero is a measurement, not a shrug. |
| Failure modes | How the job goes wrong, cited to [fitness-harness](../../freehand/studio/fitness-harness.md) requirement ids where the harness reaches the job. |
| Home | The layer that answers it: core surface, optional module, recipe, named React escape, or didactic refusal. |
| Owner | The bead accountable for carrying the answer to done. |
| Executable witness | What proves it. A cited path exists today; otherwise the artefact is named and owed by a bead. |

A witness cell always names the proof, not just its status: a reader should be able to tell what would have to run before the row could go green.

## Maintenance rule

1. **A row updates when its witness lands.** The PR that lands a witness replaces `owed by rf2-hic-NNN` with the artefact path, in the same PR. A closed bead whose row here still says "owed" is drift, and the checkpoint-correction ledger (rf2-hic-073) is where that gets recorded.
2. **Absence from a census is never evidence that a job is unimportant.** A zero in the frequency column is an argument against universal syntax and standing cost, and an argument *for* an excellent escape or an optional module. It is not a refusal.
3. **Frequency is re-measured, never edited.** The counts here are pinned to a census revision. A new number arrives with a new census pin and its citation, not by hand.
4. **The ledger's rows belong to §7.** A row is added or removed only when [specification.md §7](specification.md#7-complete-use-case-coverage) changes. New jobs go to *Candidate jobs* first.
5. **Naming questions found while mining go to the [naming ledger](naming-ledger.md)**, not here. Nobody renames mid-flow.
6. **A core proposal is compared before it earns universal cost.** Every one is measured against the smallest equivalent direct-React, Hicasso-native, or established-library control, per the [use-case compass](specification.md#21-use-case-compass). Recipes graduate to APIs only after repetition shows prose is inadequate.
