MAYOR LOOP (merge PRs).

**Run this on MOST signals — not just the cadence.** Any time you're re-invoked (a worker completing, an operator message, a loop tick), do a quick open-PR sweep and merge whatever is already green. Checking is cheap; it keeps the pipeline flowing.

**NEVER block the session waiting on CI.** Do NOT launch `gh pr checks <pr> --watch` (it occupies a slot and stalls you). Use a ONE-SHOT `gh pr checks <pr>` per open PR: merge the ones whose rollup is COMPLETE and 0-fail NOW; for any still-pending PR, leave it and re-check on the NEXT signal — the steady stream of worker-completions plus the cadence will catch it without a babysitting script.

**A green rollup must be COMPLETE, not merely clean.** Zero failures and zero pending is also what an EMPTY rollup reports — exactly what a PR shows in the seconds before its workflow runs are created, and what every PR shows while Actions is down. PR #7628 merged on a rollup read as 0/0/0 eleven seconds before its runs existed, and during the same day's Actions outage six PRs at once reported MERGEABLE with zero checks; the old wording would have taken all six. So COUNT the checks before merging: the rollup must be non-empty, every check concluded, and the total inside this repo's expected band (~86 — a partial rollup of 11 is not a green one). A gate that verifies the absence of bad news rather than the presence of good news is the same fail-open class we hunt everywhere else in this repo, and the merge decision is not exempt from it. An empty or short rollup is a re-check on the next signal — never `--admin`, and never reported as green.

Run `gh pr list --state open`. For each PR: confirm CI green, the diff matches its bead, scope did not sprawl, failure output stays actionable, and a `## Quality gates` section is present. Merge on green. Use `--admin` ONLY when a pending check is structurally irrelevant to the diff — name the gate, name why the diff cannot affect it, then merge; a failing test on the touched surface is NEVER an --admin candidate (and `MERGEABLE=UNKNOWN` is GitHub's recompute lag, which `--admin` may bypass once CI is complete and 0-fail). NEVER `git push origin --delete <branch>` before the merge succeeds (it auto-closes the PR). Verify state==MERGED via `gh pr view` before any branch cleanup. After EACH merge (don't batch): `git pull --ff-only` immediately, verify the worker closed its bead (close it with a concrete cross-ref reason if not), and record the decision in the bead. A real, repeated touched-surface failure is NOT a flake — dispatch a fix-worker to the same branch (run the ACTUAL failing gate, not a local proxy), never --admin past it. Honor any active operator pause. If no open PRs, say so and stop.
