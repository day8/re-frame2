description: Mayor Loop — worktree hygiene (≈60m cadence). Prune merged worktrees/branches; never touch open-PR worktrees.
---
MAYOR LOOP (worktree hygiene). Run `git worktree list`, `git branch --list 'worker/*'`, `git branch -r --list 'origin/worker/*'`. For each worker worktree: verify its PR via `gh pr view <#> --json state` — only if state==MERGED, prune it — but mind the `node_modules` junction. Worker worktrees junction `implementation/node_modules` into the mayor checkout's REAL `node_modules`, so `git worktree remove` (especially `--force`) follows that reparse point and deletes THROUGH it, emptying the mayor's real `node_modules`; recovery is an `npm install` in the mayor tree, and until someone notices every gate run from the mayor checkout fails looking like something else. So, in order: (1) remove the junction reparse point WITHOUT recursing into its target — PowerShell-native, with `$p` set to the forward-slash path of `<worktree>/implementation/node_modules`: `[System.IO.Directory]::Delete($p, $false)` (the `$false` is non-recursive — it drops only the junction, never the target); (2) VERIFY it is gone — `Test-Path $p` must print `False`; (3) THEN `git worktree remove <path>`. Never chain neutralize+remove in a single step. Canary each reap batch: `ls implementation/node_modules | wc -l` in the mayor tree must read the baseline (101) both before and after — a smaller count means the junction was followed and the mayor tree needs `npm install`. (On Windows a shadow-cljs/Node JVM may still hold a file lock and removal fails with "Device or resource busy" / "Permission denied" — that is harmless, leave it locked and note it.) Delete merged local + origin worker branches (NEVER delete a branch whose PR is not verifiably MERGED). Then `git remote prune origin` for stale tracking refs and clear any stray stashes. NEVER touch a worktree whose PR is still open. Report what was pruned, what was left locked, and which (if any) needs a process-kill or reboot to clear.
