# Resources prompt review

Reviewed the Grok and Fable sibling prompts on 2026-09-14 for task `rf2-11w9f`. The [read receipt](read-receipt.json) pins both copies; [Astra's previous prompt](before-sibling-review.md) is preserved. Only Astra's research brief was revised.

Useful additions adopted:

- **Both siblings:** explicitly reconcile the shipped migration-page parity scorecard with actual tests and current behavior; make the literal first-session walkthrough and the Resources/managed-HTTP comparison concrete.
- **Grok:** inspect default freshness policy rather than crediting fewer requests without considering freshness; retain a small set of opportunities and a rerunnable instrument. Astra extends this to separate native defaults from matched-policy comparisons.
- **Fable:** compare the first read with extending an established app; inspect classification and replay boundaries; include schema/editor ergonomics, concrete agent authoring, Story fixtures and declaration-driven tooling as bounded opportunities.
- **Fable:** consider TanStack DB as an adjacent development that may change a job. Check its release status and separate-package costs before attributing any advantage. A failed fetch of its documentation was followed by the [official repository](https://github.com/TanStack/db); the prompt asks the researcher to verify the then-current release, rather than freezing today's status.
- **Further refinements:** distinguish dynamic declarations from a fully static dependency graph, application/backend effects from client restore, and changed-source locality from simplistic declaration counts. Make row-specific rerun triggers explicit.

Not adopted:

- Weighted totals, a required competitive win/loss as an experimental control, or the requirement that a useful advantage be impossible elsewhere.
- Treating absence from Conduit as proof that a feature is spec-only; counting a conformance fixture as intrinsically stronger than a relevant executable test; or assuming failure to beat the HTTP sibling decides the TanStack comparison.
- Broad claims that competitors necessarily fetch from render, use unsafe global caches, lack classification equivalents or require naive rollback. These remain questions to test against supported approaches.
- Expanding the assignment into a survey of every mentioned library, or treating a recorded architectural refusal as automatic satisfaction of the user's broader parity objective.

The revised [prompt](../prompt.md) retains categorical job-level findings, source/runtime attribution, controlled concurrency probes, a 2,500–4,000-word target for the main report, and restrained recommendations. This task improved the assignment; it did not execute the Resources report.
