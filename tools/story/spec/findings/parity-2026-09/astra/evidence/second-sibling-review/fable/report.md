### 2.4 The first reading, in prose

Story is **not a Storybook clone that is behind**; it is a different tool that happens to cover Storybook's daily surface and then keeps going, and its weakest hour is its first. A Storybook user who gets past the install finds what they expect where they expect it — a sidebar with search, mode tabs (real ARIA tabs), a canvas, controls and inspectors on the right, docs beside the example, a Tests tab with pass/fail counts, a share dialog, a matrix view — and a first-run help dialog that explains the layout and the keyboard shortcuts. The `018` §3.1 parity bars are met or exceeded on Docs, Matrices, Sharing and Status; Controls is met in code and missed in practice, because no shipped example registers a view schema, so the derived controls the audit scores as a WIN never appear on any screen a newcomer opens.

The same user then meets things Storybook cannot have without re-frame2's substrate: every variant runs in its own frame (the grid cells are isolated; the chip says "fresh frame"); every run leaves an epoch tape with `:db-before/:db-after/:effects/:trace-events` per beat; the Xray embed shows the event → db → sub → render cascade with source coordinates; the fidelity rung is declared and enforced; effect stubs are positional data in the plan hash. And an agent gets all of this over stdio with no browser in the loop.

What that user also meets, and what this report exists to say plainly: a promotion that turns a red run into a green variant; an upgrade scaffold that cannot be pasted; a placeholder in the Tests pane where the failed-assertion → evidence link should be; an Explain panel that says "ARGS not available" for a variant that has args; a sidebar that counts a five-cell grid as zero (its counter reads the body's `:variants`, and the auto grid has none — `sidebar.cljs:621–627`); a "frozen" result contract whose two hash keys are not in the result; a skill leaf promising a validation the MCP write tool does not perform; and, once one looks, a login heading painted in Story's own chrome colour because the canvas is one document. None of these is deep. All of them turn "this is better" into "this is not finished" in a first session — and the first two turn it into "this is not true".

## 4. The advantage thesis, from re-frame2's substrate

`018-Story-UI-North-Star.md` §3.1 is the claim under test: "Parity is a quality bar, not a checklist of nouns… Story should deliberately surpass Storybook where re-frame2 gives leverage", with eight surpass items and four Storybook patterns not to copy. This section says which are **BUILT** (exercised at the sha), **SPECIFIED** (promised, code partial) or **IMAGINED** (neither), and why the substrate makes the built ones possible.

### 4.1 The substrate levers

Five things a component-story tool for React, Vue or Swift does not have, each named to the spec that owns it:

- **Frames** (`spec/002-Frames.md`): an app-db, registrar view and effect table per variant with `:preset :story` (`frames.cljc:18`). This is why a grid of nine states is nine isolated apps, and why `force-fx-stub` is a per-frame `:fx-overrides` entry rather than a module mock. It isolates state; it does not isolate the document (A7).
- **Epochs and the trace bus** (`spec/009-Instrumentation.md`): every dispatch is a recorded beat with before/after db, effects, sub runs, renders and trace events. This is why the run result *is* evidence and why Xray can show causality with source coordinates inside the workshop.
- **Schemas → controls** (`spec/010`): a view's Malli schema is the controls spec, so `argTypes` is derived — when a schema exists.
- **Effects as data** (`:fx` vectors, `reg-fx` with `(fn [ctx args])`): the side-effect boundary is enumerable, so "was `:http` emitted" is an assertion and "replace `:http` for this frame" is a decorator tuple, both hashed into the plan.
- **Data-only registration** (`spec/007-Stories.md`): a variant has no function slots, so it is diffable, promotable, transmittable over MCP, and identical on JVM and CLJS.

Storybook's equivalents are `play` (imperative), decorators (opaque, per `018`'s own words), `sb.mock`/MSW (module/network), and CSF (a module). Astra's caution stays in view: none of this is impossible in JavaScript — a store per provider, module mocks, DevTools — so the advantage has to show up as fewer translations between activities, not as a list of things Storybook cannot do. Histoire, Ladle and Cosmos are the same shape with smaller ecosystems; SwiftUI `#Preview` and Compose `@Preview` are compile-time previews with no runtime tape; devcards' `deftest` cards were the closest ancestor (2020), and Nubank workspaces and Portfolio did the component grid first (grok) — what is new against Storybook is five app-dbs of one real machine, not the grid.

### 4.4 How to falsify the thesis

The surplus rows are structural: they say what the substrate makes possible, not that a programmer gets more done.
