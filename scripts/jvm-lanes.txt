# Every JVM lane in the repo, one row per artefact.
#
# This file says WHICH lanes exist and WHEN they run. HOW each one runs, meaning
# its classpath, selectors and posture, stays in the artefact's own deps.edn,
# so the rows never become a second build definition.
#
# Five whitespace-separated fields. `#` starts a comment.
#
#   dir        the artefact directory: the one holding its deps.edn
#   aliases    each `clojure -M:<alias>` that CI runs there, comma-separated,
#              `test` first. On a `matrix` row each alias is one leg of
#              test.yml's `jvm` job, named `JVM <dir> (<alias>)`
#   slow       `slow` when the artefact's `:slow-test` alias holds the
#              ^:slow / ^:stress tests that `:test` excludes, otherwise `-`
#   predicate  the classifier output that schedules the row, or `always`
#   ci         `matrix`, or the id of the hand-written test.yml job that runs
#              an artefact whose lane needs more than a plain alias call
#
# Readers: scripts/jvm-lanes.sh (shell and workflows) and scripts/jvm_lanes.py
# (Python). The rows under implementation/ are the roster of
# scripts/test-jvm-implementation.sh and the fast-PR spine's JVM tier. Every
# other row is the roster of scripts/test-jvm-tools.sh. Both rosters run
# `clojure -M:test` in row order. The `slow` rows run nightly in
# expensive-tests.yml's `jvm-slow-tests` and locally in
# scripts/test-rigorous-local.sh. scripts/check_jvm_lanes.py holds every row
# against the deps.edn files and against test.yml.
#
# A change here re-tiers the matrix, so the classifier arms every output for
# it, the same as for a workflow edit.

# dir                                   aliases              slow  predicate                   ci
