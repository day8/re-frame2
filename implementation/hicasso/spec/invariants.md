# Hicasso invariants

One page to check a change against: the fifteen invariants the product commits to.
Every row is transcribed from the [product specification](../../../docs/design/hicasso/product/specification.md),
the [design laws](../../../docs/design/hicasso/product/lanes/design-laws.md), the
[public-language lane](../../../docs/design/hicasso/product/lanes/ergonomics-api.md) or the
[decision brief](../../../docs/design/hicasso/product/decision-brief.md), and cites its owner.
**Where a row and its owner disagree the owner governs and the row is the defect** — fix the
row; questions are not settled here.

Cite key: `§n` is a [product specification](../../../docs/design/hicasso/product/specification.md) section; a capitalised word plus a number, such as *React 5*, is that numbered law in the named section of the [design laws](../../../docs/design/hicasso/product/lanes/design-laws.md).

| # | Invariant | What it requires, and what it forbids | Owner |
|---|---|---|---|
| I1 | One interpreted semantics | Interpreted Hiccup is the only ordinary meaning. No `:fast` flag, compiled body, alternate renderer, automatic specialization, or profile-dependent meaning; no public option selects an execution mode. | [§3.1](../../../docs/design/hicasso/product/specification.md#31-one-language-and-one-state-owner) · [React 5](../../../docs/design/hicasso/product/lanes/design-laws.md#react-and-ownership) · [Economics 5](../../../docs/design/hicasso/product/lanes/design-laws.md#economics-and-scope) |
| I2 | Two explicit languages | `[...]` always means interpreted Hiccup; a React element passes through unchanged. Nothing analyses or rewrites a `defview` body; native construction is explicit — a React element a body returns, or a React island mounted through `h/defhost`. | [Native 2](../../../docs/design/hicasso/product/lanes/design-laws.md#native-boundary) · [§3.1](../../../docs/design/hicasso/product/specification.md#31-one-language-and-one-state-owner) |
| I3 | One state owner | re-frame2 owns application state. Subscriptions are the only adapter reactive source; the re-frame2 state commit is the application write clock. No ratom-like second model. | [§3.1](../../../docs/design/hicasso/product/specification.md#31-one-language-and-one-state-owner) · [State 1–2](../../../docs/design/hicasso/product/lanes/design-laws.md#state-and-reactivity) |
| I4 | Named state pressure valves | Durable or application-visible state, including drafts affecting validation, navigation, replay, or collaboration, takes an explicit re-frame2 address. High-frequency state that only operates a native widget may stay host-private and is diagnostic-opaque by contract. DOM-owned state is an explicit interop choice, never a hidden substitute. | [§3.1](../../../docs/design/hicasso/product/specification.md#31-one-language-and-one-state-owner) · [State 3](../../../docs/design/hicasso/product/lanes/design-laws.md#state-and-reactivity) |
| I5 | Render probes, commit owns | Render is speculative: it probes reads, acquires no durable ownership, and publishes no committed evidence. The selected commit reconciles exactly its read and host set; disconnect releases it. Abandoned renders leave no subscriptions and no diagnostic records; teardown is exact and testable, with zero residue after quiescence. | [§3.2](../../../docs/design/hicasso/product/specification.md#32-react-owns-react-facts) · [React 1–3](../../../docs/design/hicasso/product/lanes/design-laws.md#react-and-ownership) · narrowed by [rf2-hic-013](../../../docs/design/hicasso/product/invariants.md#the-callback-and-frame-incarnation-rule-rf2-hic-013) and [rf2-hic-015](../../../docs/design/hicasso/product/invariants.md#the-hmr-contract-rf2-hic-015) |
| I6 | React owns React facts | React owns component identity, hooks, refs, effects, errors, context, concurrency, Suspense, Activity, hydration, commit, and DOM reconciliation. Hicasso uses React's public contracts rather than simulating them. | [§3.2](../../../docs/design/hicasso/product/specification.md#32-react-owns-react-facts) · [React 4](../../../docs/design/hicasso/product/lanes/design-laws.md#react-and-ownership) |
| I7 | The ambient-read extent | `sub` is legal during the direct synchronous execution of the active body, helpers, branches, and loops included. A read deferred through a callback, promise, timer, lazy sequence, or other escaped extent refuses with source and recovery. Dynamic reads reconcile from the selected render without a general per-boundary dependency ledger. Enforcement reaches the structure a body returns: a deferral parked in a mutable reference is outside it, and forcing that read inside another body is undefined conduct rather than a refusal. | [§3.3](../../../docs/design/hicasso/product/specification.md#33-dynamic-composition-is-a-feature) · [State 4–5](../../../docs/design/hicasso/product/lanes/design-laws.md#state-and-reactivity) · narrowed by [rf2-hic-011](../../../docs/design/hicasso/product/invariants.md#the-ambient-read-extent-as-enforced-rf2-hic-011) |
| I8 | Capability pays rent | A facility used by few boundaries adds no standing machinery to all boundaries. Optional libraries and the native namespace are separately reachable and absent from a production bundle that does not use them. Stable callback machinery, read ledgers, static manifests, and lifecycle histories require a measured caller before they exist. Standing cost is the first budget; Hiccup lowering is the second. | [§3.4](../../../docs/design/hicasso/product/specification.md#34-capability-pays-rent) · [Economics 1–2](../../../docs/design/hicasso/product/lanes/design-laws.md#economics-and-scope) |
| I9 | The two-hook ceiling | The ordinary boundary's context plus external-store hooks consume the whole budget. Optional capabilities may not add a hook to every boundary or a universal ownership graph; freeing or replacing one requires its own correctness and whole-shell measurement. Measure the do-nothing and read-free boundary whenever the shell changes. | [§3.4](../../../docs/design/hicasso/product/specification.md#34-capability-pays-rent) · [State 6](../../../docs/design/hicasso/product/lanes/design-laws.md#state-and-reactivity) · narrowed by [rf2-hic-018](../../../docs/design/hicasso/product/invariants.md#the-two-hook-ceiling-and-the-chosen-collector-substrate-rf2-hic-018) |
| I10 | Data by default | Markup and ordinary event intent are data; an explicit handler form covers value-first or calculated events; ordinary functions cross host boundaries unchanged when a JavaScript API genuinely expects executable behaviour. What does **not** vary by position is ownership and prevention: a callback owns its own event everywhere and is never auto-prevented. What **does** vary is the contract the `h/event` carrier is read under — HD-024 tabulates event and render, inferred from the position at a native tag and at a host alike, with a `defhost` `:callbacks` override for the on*-named render props some vendors ship — and it never varies *silently*: the marked form at a declared `:slots` position refuses with `:rf.error/hicasso-host-unclaimed-callback`, named at the position. Prevention is explicit via `::h/prevent` at every position except `:on-submit`, whose data spelling auto-prevents, and no second auto-preventing position may be added. *This cell read* "Position never silently changes the meaning of the same function form" *until 2026-08-15 (`rf2-0fd3b`): that reading collapsed the two, and section 3's `h/event` row carries the table.* | [§3.5](../../../docs/design/hicasso/product/specification.md#35-data-by-default-functions-when-the-contract-is-executable) · [Language 1, 4](../../../docs/design/hicasso/product/lanes/design-laws.md#language-and-interop) |
| I11 | Loud, stable failure | Every refusal carries a stable error id, source coordinate, view, frame where relevant, tree path or host-prop position, offending value, expected shape, and actionable recovery. Unknown, opaque, capped, and uncorrelated are first-class results, never rendered as an authoritative empty one. | [§3.6](../../../docs/design/hicasso/product/specification.md#36-loud-stable-failure) · [Language 6](../../../docs/design/hicasso/product/lanes/design-laws.md#language-and-interop) · [Evidence 6](../../../docs/design/hicasso/product/lanes/design-laws.md#evidence-and-tools) |
| I12 | Production erasure | Diagnostic and profiling sentinels are absent from default production bundles; tool evidence is versioned, privacy-projected, loss-accounted, and absent from production. Developer products are development-only. | [§6](../../../docs/design/hicasso/product/specification.md#6-performance-contract) · [§10](../../../docs/design/hicasso/product/specification.md#10-xray-and-runtime-evidence) · [Evidence 5](../../../docs/design/hicasso/product/lanes/design-laws.md#evidence-and-tools) |
| I13 | Interop and SSR are core contracts | Every public view, host, root, resource boundary, and native escape renders deterministically on the server or refuses with recovery, and has explicit hydration behaviour under the [canonical matrix](../../../docs/design/hicasso/product/lanes/react-compatibility-notes.md#public-surface-ssrhydration-matrix). Only the deployable Node service is optional. | [§1](../../../docs/design/hicasso/product/specification.md#1-product-shape) · [Language 8](../../../docs/design/hicasso/product/lanes/design-laws.md#language-and-interop) |
| I14 | One facade | Applications get one obvious `h` facade; optional capabilities live in clearly named namespaces with bundle-reachability proofs, and no benchmark-only aliases. | [§4](../../../docs/design/hicasso/product/specification.md#4-target-programming-model) · [Language 7](../../../docs/design/hicasso/product/lanes/design-laws.md#language-and-interop) |
| I15 | Controlled fields are a framework law | Interpreted controlled fields converge within the turn that edited them, echo only committed state, and preserve caret, selection, and in-flight composition across that echo. A rejected or normalized value echoes as the committed one rather than being silently accepted, and reset is an explicit revision that preserves element identity. Owned `value`, `checked`, handler, key, and revision slots win by presence, not truthiness; a forwarded attribute cannot replace one. Each field kind and edge in the §4.2 roster carries an explicit support or refusal policy; drafts, touched/submit-attempt validation, and mutation status stay out of the boundary shell. | [§4.2](../../../docs/design/hicasso/product/specification.md#42-controlled-fields) · [Language 3](../../../docs/design/hicasso/product/lanes/design-laws.md#language-and-interop) · [authoring laws 6–7](../../../docs/design/hicasso/product/lanes/ergonomics-api.md#authoring-laws) |
